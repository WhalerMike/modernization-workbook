# Chapter 05: PIM for Groups and the PRV groups

Notes for developers on the code behind *Building Privileged Access*, Chapter 05 ([`05-pim-for-groups.md`](../../../docs/project-plans/developer-workbooks/privileged-access/05-pim-for-groups.md)). The chapter is the reference; this page says where things are.

## Files

| File | What it is |
|---|---|
| `powershell/PimGroups/PimGroups.psm1` | The module. Imports `PrivilegedAccess` only for `Get-PaCloud`. |
| `Invoke-PaPimGroups.ps1` | The entry script: findings, plan, diff, manifest; a dry run unless `-Apply`. `-Cloud` is mandatory. |
| `config/calls-ch05.json` | Every call, with its least-privileged permission and Learn page. Reads belong to `pim-groups-read` and `pim-groups-apply`; writes to `pim-groups-apply` only. |
| `config/prv-group-policy.json` | *Design guidance*: the member and owner policy for each tier. |
| `tests/PimForGroups.Tests.ps1` | 40 Pester tests: 10 for Microsoft's pinned samples, 30 for the module. |
| `tests/PimForGroupsSampleHarness.ps1` | Extracts the `http` requests from `examples/third_party/graph-pim-for-groups-pages` and sends them, unmodified, to the fake. |
| `tests/fixtures/ch05/tenant.json` | The fictional tenant as the fake serves it. Policies are shortened to the five managed rules. |
| `tests/fixtures/ch05/inputs/prv-groups.json` | The fictional desired state. |

## Functions

- `Read-PaPrvGroupConfig`, `Test-PaPrvGroupConfig`: read and check the desired state (PA-PG-01, -05, -06, -07, -08).
- `New-PaPgClient`, `Invoke-PaPgList`: declared calls only, the cloud's own host only, every page.
- `Get-PaPgTenantState`, `Test-PaPgTenant`: read the tenant and check it (PA-PG-02 to -09).
- `New-PaPgRuleSet`, `Compare-PaPgPolicy`: the five managed policy rules, in Learn's shapes, and their differences.
- `New-PaPimGroupPlan`, `Test-PaPgPlanGuard`, `Invoke-PaPgPlan`: the plan, its guards (PA-PG-G1 to -G7), and the dry run or `-Apply`.
- `New-PaPgFixtureInvoker`, `New-PaPgLiveInvoker`: the fake and the live invoker (`Invoke-MgGraphRequest`).
- `Export-PaPgRun`: the run's files and a manifest with each file's SHA-256 and every request.

## Rules for changes

- A new call goes in `config/calls-ch05.json` with its permission and Learn page, or the client refuses it.
- A write is never sent without `-Apply`, and never when a guard fails.
- The pinned pages are never edited; update the snapshot only in a reviewed pull request.
- Run `Invoke-Pester -Path tests` before a pull request; all chapters' tests run together.
