## Permissions

`Get-PaEvidencePermission -Task evidence-run` prints the union of the three tasks. The audit read adds one application permission, `AuditLog.Read.All`; for a delegated read, Reports Reader is the least-privileged role. Azure needs Reader on each scope the inventory reads.

## The run folder

```
<run-id>/run.json            schema fmp-pa-run/1: run ID, as-of, cloud, tenant ID, mode, audit window, each task's status and manifest SHA-256
<run-id>/inventory/          Chapter 01's output, as Invoke-PaInventory.ps1 wrote it
<run-id>/emergency/          Chapter 02's output, as Invoke-PaEmergencyCheck.ps1 wrote it
<run-id>/pim-audit/          events.json, requests.json, summary.json, findings.json, manifest.json (IDs only, no names)
```

A task that fails is recorded as `Error` in `run.json` and leaves no folder. The comparison then treats its findings as unverified, never as resolved.

## Line endings

Chapter 01's and Chapter 02's `Export-PaRun` writes JSON with the platform's line endings, so a run made on Windows has CRLF in those files, and each file's hash is in its manifest. `tests/fixtures/pa-runs` in the drift pipeline holds two runs made on Windows, kept byte for byte by a `.gitattributes` there (`* -text`). This chapter's own files are written with LF on every platform.
