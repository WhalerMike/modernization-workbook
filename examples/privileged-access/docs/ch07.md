# Chapter 07: access reviews of privileged roles

Notes for the code behind [Chapter 07](../../../docs/project-plans/developer-workbooks/privileged-access/07-access-reviews-of-privileged-roles.md) of the developer workbook *Building Privileged Access*. They live here, not in `../README.md`, so this chapter's change touches only files of its own.

Unlike Chapters 01 and 02, this code can write to a tenant. It writes only with `-Apply`, only the series its dry run lists, and it never deletes.

## Start with Microsoft's sample

Learn's tutorial *Review access to administrative roles using access reviews APIs* is pinned unmodified in [`../../third_party/graph-access-reviews-roles-tutorial`](../../third_party/graph-access-reviews-roles-tutorial/SNAPSHOT.md). `tests/AccessReviewsSampleHarness.ps1` extracts its HTTP requests, and the first block of `tests/AccessReviews.Tests.ps1` runs the create request against the fake and pins what the sample does and leaves out.

## Tasks and permissions

`Get-PaArRequiredPermission -Task <task>` prints a task's permissions. Give each task its own identity.

| Task | Microsoft Graph (application) | Azure | Writes |
|---|---|---|---|
| `access-reviews-plan` | `AccessReview.Read.All` | Reader on each subscription with an Azure series | none |
| `access-reviews-apply` | `AccessReview.ReadWrite.All` | User Access Administrator on each subscription with an Azure series | POST and PUT of definitions, with `-Apply` only |
| `access-reviews-evidence` | `AccessReview.Read.All` | Reader | none |

## Rules

Plan checks, on every body it builds: PA-AR-01 (no reviewers, a self-review), 02 (no fallback reviewer), 03 (reviewer description missing or over 256 characters), 04 (duration too long for the recurrence), 05 (auto-apply off), 06 (Deny or Recommendation on silence over active assignments of a role the emergency accounts hold: the lockout), 07 (no-response default isn't Deny), 08 (justification not required), 09 (cadence doesn't match the tier), 10 (start date in the past), 11 (a group as reviewer of an Azure series), 12 (two series in the tenant share a name), 13 (a series with the managed prefix that the JSON doesn't list). `-Apply` refuses any plan with a Finding.

Evidence checks: PA-AR-E01 (series missing), E02 (no closed instance within the cadence window), E03 (a denial that didn't apply), E04 (not reviewed), E05 (approved without justification), E06 (a principal reviewed their own access), E07 (many identical decisions by one reviewer within minutes), E08 (an emergency account denied).

## Azure role reviews are preview

Azure role series go through Resource Manager `Microsoft.Authorization/accessReviewScheduleDefinitions`, whose versions on Learn are all previews (`2021-12-01-preview` here). The plan builds and compares them; `-Apply` sends them only with `-IncludePreview`. Whether the `scope` fields the code sends are writable through that PUT is open (workbook research gaps).
