# Chapter 04: PIM for Microsoft Entra roles as code

Notes for the code behind [Chapter 04 of *Building Privileged Access*](../../../docs/project-plans/developer-workbooks/privileged-access/04-pim-for-entra-roles-as-code.md). It lives beside Chapters 01 and 02 in this example, in files of its own.

Illustrative: tested against a fictional tenant served by a fake Graph, not proven against a production tenant. Unlike Chapters 01 and 02, this code can write to a tenant, but only with `-Apply`; the default is a dry run.

## Layout

```
Invoke-PaPimRoleSettings.ps1                   plan one rollout wave (dry run); -Apply; -Apply -Convert; -Apply -RestoreFrom (back-out)
config/calls-ch04.json                         every call: method, path, least-privileged permission, delegated role, Learn page
config/pim-ch04/roles/*.json                   one reviewed file per role: Book 04, Appendix B as code (22 roles)
config/pim-ch04/tiers.json                     Learn's bounds, the program's caps per tier, and the rollout waves
powershell/PimEntraRoles/PimEntraRoles.psm1    the module: role files, rules, checks, client, diff, plan, apply, fake
tests/PimEntraRoles.Tests.ps1                  Pester 5: Learn's samples as published, then the module and the entry script
tests/PimLearnSampleHarness.ps1                extracts the HTTP requests from the pinned Learn pages
tests/fixtures/ch04/tenant.json                a fictional tenant: 22 role policies, eligibility, active assignments
tests/fixtures/ch04/inputs/pim-bindings.json   that tenant's approver groups and PRV groups, by object ID
tests/fixtures/ch04/inputs/confirmed-activations.csv   activations confirmed through the PRV group, with tickets
```

It reuses Chapter 01's cloud table (`Get-PaCloud`) and exceptions list, and Chapter 02's `emergency-access.json`, by importing the `PrivilegedAccess` module. It doesn't change that module.

## Permissions

`Get-PaPimRequiredPermission -Task <task>` prints them; `config/calls-ch04.json` names the Learn page for each.

| Task | Microsoft Graph (application) | Delegated role |
|---|---|---|
| `pim-plan` (dry run) | `RoleManagementPolicy.Read.Directory`, `RoleEligibilitySchedule.Read.Directory`, `RoleAssignmentSchedule.Read.Directory` | Global Reader |
| `pim-apply` (`-Apply`) | the three reads, `RoleManagementPolicy.ReadWrite.Directory`, `RoleEligibilitySchedule.ReadWrite.Directory` | Privileged Role Administrator |
| `pim-convert` (`-Apply -Convert`) | the three reads, `RoleAssignmentSchedule.ReadWrite.Directory` | Privileged Role Administrator |

Grant a reader app the `pim-plan` permissions only. Run `-Apply` from a separate, reviewed pipeline identity.

## Guards

- PA-PIM-01: approval required with no approver (half of Learn's documented lockout).
- PA-PIM-02: fewer emergency accounts with permanent active Global Administrator than `emergency-access.json` requires (the other half).
- PA-PIM-03: an approver group that is also the role's eligible group.
- PA-PIM-04: a role file outside Learn's bounds or its tier's cap.
- PA-PIM-05: an authentication context; `-Apply` needs `-ActivationGateChecked` once its Conditional Access policy is On.
- PA-PIM-06: no policy for the role in the tenant.
- PA-PIM-07: an earlier rollout wave doesn't match its files yet.
- PA-PIM-08 and PA-PIM-09: eligibility outside the PRV group, and standing assignments (reported; users are removed only after their activation is confirmed).

Any Finding blocks `-Apply`. Every run writes `manifest.json` with each request, the SHA-256 of each write's body and of each file, and `before.json`, the wave's seven managed rules per role as the tenant held them before the run. `-Apply -RestoreFrom <run folder>` puts those rules back and removes the eligibility that run created.
