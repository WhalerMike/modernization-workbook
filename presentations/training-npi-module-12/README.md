# Non-Person Identity learning path, Module 12: Migrate a service account

**Deck name: Training_NPI_Module_12.** The narrated deck for [Module 12: Migrate a service account, from a user account to a gMSA, a dMSA or Microsoft Entra](../../docs/training/non-person-identity/12-service-account-migration.md), in the [Non-Person Identity learning path](../../docs/training/non-person-identity/index.md). It teaches the module the way Microsoft Learn does: the learning objectives, the concepts, **Try it** slides with the real Lab 1 commands and output, Lab 2, the federal requirement and the evidence an ISSO keeps, a two-question knowledge check, and the summary. It is built with the shared kit in [`../_build/`](../_build/README.md) and the training decks' helpers in [`../training-ms-automation-module-1/shared.js`](../training-ms-automation-module-1/shared.js). The companion guide has its own deck, [`../guide-service-account-migration/`](../guide-service-account-migration/README.md), which walks the guide step by step; this deck teaches the module and points to the guide. This folder sits outside `docs/`, so the site doesn't render it.

| Part | Covers |
|---|---|
| Introduction | Title; why move one account by hand, with Microsoft Learn's commands, before you approve a plan (three moves: a gMSA, a Windows Server 2025 dMSA, a Microsoft Entra workload identity); learning objectives and prerequisites |
| Concepts | Unit 1: who holds each kind of credential and which kinds speak Kerberos; the decision path (the first yes is the target, with its Chapter 03 disposition) and the track's rules. Unit 2: Migrations A and B in Learn's order, and the special cases to stop on. Unit 3: Migration C, Learn's order of preference for a credential, the four targets and what can't move |
| Lab | Try it: Lab 1 steps 1 to 7, Chapter 06's and Chapter 05's checks on the kit's fixtures: the runs and Learn's steps as 17 tests, the Kerberos check and plan, the two migrations the plan sends (`CreateGmsa`, `CompleteDmsaMigration`), the dry run by approved hash, and Chapter 05's conversions with their parallel runs; Lab 2, the moves for real in a test domain, by hand or through Chapter 06's Lab 2 (not run by the authors) |
| Check and summary | The federal requirement (AC-6, IA-5, CM-3, AC-2(3), IA-9, CM-8 and AC-2) and evidence; two knowledge-check questions with answers; the summary and the next step |

The narration was recorded on November 21, 2026 from the module as approved. The MP4, the narrated deck and the plain deck aren't on a Release yet. The narration runs about 13 minutes.

Build (Git Bash): `source /c/tmp/deckenv.sh`, then `FIT=1 node presentations/training-npi-module-12/build.js presentations/training-npi-module-12/Training_NPI_Module_12.pptx`. Then `narrate.py` and `captions.py`, and on a workstation where PowerPoint is free, `qa_export.ps1`, `build_narrated.ps1` and `export_mp4.ps1`, as in the kit's README. The build runs the shared checks: title length and uniqueness, Sources length, and overflow warnings, including the code panel's width and height.

## Notes and sourcing

Each slide's speaker notes are the narration, then a `Workbook:` reference to the module's units, which isn't spoken. Every fact on a slide comes from the module page, the companion guide [Service Accounts](../../docs/books/guides/service-account-migration.md) sections it sends the learner to (the kinds of service identity compared, the decision path, the program's rules, Migrations A, B and C, the special cases, the dangers, and the federal requirements and evidence), workbook [Chapter 06](../../docs/project-plans/developer-workbooks/non-person-identity/06-gmsa-dmsa-and-the-kerberos-island.md) and [Chapter 05](../../docs/project-plans/developer-workbooks/non-person-identity/05-workload-identity-federation-and-managed-identities.md), or the code and fixtures in [`examples/non-person-identity`](../../examples/non-person-identity/README.md) (`Invoke-NpiKerberosIsland.ps1`, `Invoke-NpiKerberosIslandAction.ps1`, `Invoke-NpiFederation.ps1`, `tests/KerberosIslandSamples.Tests.ps1`); the deck adds none. The **Try it** output is the module page's Lab 1, which reruns parts of Chapter 06's and Chapter 05's Lab 1, and matches the kit's captures [`data/kit-captures/npi/06-1.txt`](../../data/kit-captures/npi/06-1.txt), `06-2.txt`, `06-4.txt`, `06-8.txt` and `05-3.txt`, written by `scripts/kit_captures.py` on the fictional fixtures. Long commands and output are trimmed, wrapped and reflowed, with "..." marking each cut, as the slides say. The module's labels carry over: the mapping of files to KSIs is design guidance, and Lab 2 hasn't been run by the authors. Approval is SailPoint, reached through the agency's system access management tool; the deck names no agency.
