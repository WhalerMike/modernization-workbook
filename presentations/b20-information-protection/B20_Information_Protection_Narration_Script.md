# Book 20 — Information Protection & Microsoft Purview — narration script (practice copy)

## Slide 1 — Protection That Travels With the Data

Welcome. This briefing comes from Information Protection and Microsoft Purview, a book of the Federal Modernization Workbook. One thing first: the book is a draft. Every page is awaiting the editor's review, and it isn't part of Release 2.0, the baseline edition. It's written for C I Os and CISOs, data owners, records and privacy officials, Purview engineers, and ISSOs. I'll take four questions. Why does protection have to travel with the data? What does the program build with Microsoft Purview? Who runs it? And how do you roll it out and prove it works? The short version: identity, device and network controls decide who reaches a file. Only a classification decided in advance can say what the file is, and that decision has to be written down before a single label is published.

## Slide 2 — Upstream controls can't see the payload

A Zero Trust program usually builds identity, devices and the network first. Each of those controls passes a legitimate user on a compliant device sending a file to an approved destination, whatever the file holds. Nothing upstream said what the payload was. CISA's Zero Trust Maturity Model makes the same point with a Data pillar of its own. Three things make perimeter thinking fail for data. It moves more than people do: an export becomes an attachment, a OneDrive file, a chat paste and an AI summary, and each copy inherits none of the original's access controls. Access is granted to containers, not to content. And the agency can't protect what it hasn't named. Microsoft's sensitivity label is what lets protection travel. It's stored in clear text in the item's metadata, it stays with the content wherever it's saved, and so does any encryption it applies. But a label is only as good as the class it stands for.

## Slide 3 — Decide the classes before any label

So the first deliverable is a set of written decisions, not a label policy. A data class is the agency's name for a kind of information that needs one handling outcome. The class register lists them, one row each, and every later label, D L P rule and auto-labeling policy cites the class it serves. Each class has a data owner, an official rather than an administrator, who decides its handling and approves exceptions. A federal agency inherits several of these decisions. The C U I rule, thirty-two C F R part two thousand two, and the C U I Registry decide which categories the agency holds and how they're marked. Category markings are optional for C U I Basic and mandatory for Specified. The Privacy Act, records schedules and fips one ninety-nine decide the rest, and C U I Basic sets a confidentiality floor of moderate. And each outcome has to be testable. Sensitive isn't an outcome. Encrypted so only a named group can open it, and never sent outside the tenant, is.

## Slide 4 — Three boundaries, four planes, a small taxonomy

The book's reference architecture has three trust boundaries and four control planes. The boundaries are the tenant, the managed endpoint, and outside, where external recipients can't see the agency's labels at all. The planes are identity, which owns the groups that labels grant rights to; policy, which is Purview; protection, which is Rights Management and the tenant key; and monitoring, which is Purview Audit. Each plane has its own owner. The label design follows the class register, one label per class. Microsoft reports that effectiveness drops noticeably beyond five main labels, or five sublabels under one, so the taxonomy stays small: Public, Internal, C U I Basic, a category sublabel only where agency policy requires one, and one Specified sublabel per authority the agency actually holds. Container labels sit in a group of their own. Encryption grants rights to mail-enabled groups, never to individuals. And a label that doesn't encrypt is a classification signal. Once the content leaves the tenant, it protects nothing.

## Slide 5 — Defaults users rarely notice, containers that hold

A label does nothing until a policy publishes it, and the policy carries the defaults. The program defaults documents, email and meetings to Internal, and new groups and sites to Internal site. None of those encrypts, because Microsoft cautions that an encrypting default may leave external recipients unable to open the content. Mandatory labeling then makes users label before they save or send, and with a sensible default they're rarely prompted. A user can change a label but not remove it, and the program asks for a justification when someone lowers one. Containers get three labels of their own: Internal site, CUI site and CUI Specified site. Each sets privacy, guest access, external sharing, unmanaged-device access and the default sharing link. But a container label governs the site, not the files: the items inside don't inherit it. In GCC, file labels and container labels are listed as available. The default label for a SharePoint library is still in development there, and authentication contexts on labeled sites are on the engineering backlog.

## Slide 6 — Encrypt, and keep a tested way back in

Encryption is where a mistake is hardest to undo. Rights Management is usually already on: Microsoft activated it automatically for subscriptions from late February 2018 onward. So the decisions are who may encrypt during rollout, which tenant key, and who can recover content when its only authorized holder is gone. The program keeps the super user feature off, with no standing members. For a named recovery, an operator activates an approved role through PIM, turns the feature on, adds one named super user, recovers the item, and then removes both. Not through a PIM-managed group, because the service caches group membership for up to three hours. Mail uses the same service. Labels carry classification, and mail flow rules carry approved scenarios, so neither depends on a sender remembering. In SharePoint and OneDrive, turn label integration on before encrypting labels go wide; until then, encrypted files are invisible to search, eDiscovery and D L P. In GCC, Rights Management, message encryption and co-authoring on encrypted files are listed as available.

## Slide 7 — DLP from an owner's outcome, auto-labeling for the rest

Microsoft's D L P templates are a convenient start and a poor design. The program writes each policy from an outcome statement the policy owner owns. For example: content labeled C U I isn't shared or sent outside the tenant except through the approved partner path; an attempt is blocked, the user is told why, and the security monitor is alerted. Rules match labels first, a decision someone already made, and treat raw content patterns as the safety net. Overrides are logged and read every week, and exceptions name groups, sit in a register, and expire within a year. Endpoint D L P covers Windows 10 and 11, and Windows Server 2019 and later. For content nobody labeled, auto-labeling climbs a ladder: built-in types, custom types, exact data match, then trainable classifiers, only as far as false positives require. Client-side labeling recommends a label while the author works; service-side labeling applies one at rest and in mail. In GCC, D L P on every surface, auto-labeling and exact data match are listed as available.

## Slide 8 — Audit is the floor; insider risk needs a charter

Every other signal depends on audit. Audit Standard is on by default for enterprise organizations and keeps records for 180 days. Audit Premium keeps the core services' records for a year, and up to ten years with an add-on. But retention follows the license of the user who acted, so the agency's log platform, not the tenant, holds the full evidence period. Search isn't real time, either: typically sixty to ninety minutes for the main workloads. The program proves the pipeline every month with a synthetic label event, found in the tenant and in the log platform. Insider Risk Management and Communication Compliance are different: they watch named people. So before either is configured, the agency signs a charter. The CISO, the privacy official, general counsel and labor relations settle the purpose, the notice and what investigators may see, and the records officer sets how long cases are kept. Pseudonyms stay on, administrators don't investigate, and someone outside the team reviews the reviewers. In GCC, both audit tiers and the core insider risk features are listed as available.

## Slide 9 — AI inherits every permission error

AI changes the problem, not the controls. Microsoft describes Copilot's protection in a fixed order. First, permissions: it only uses content the user can already reach. Second, encryption: the user needs both the VIEW and the EXTRACT usage rights for Copilot to summarize an encrypted item, so the usage rights in each sublabel are now an AI decision. Third, labels: Copilot shows the label of what it drew on, and new content inherits the highest-priority one. That makes oversharing a disclosure path. A site shared with the whole agency was always readable; an assistant finds it in seconds. So the policy owner decides four things first: which AI apps are approved, which labels Copilot may process, what oversharing gets fixed before rollout, and who may read captured prompts. D L P for Copilot can keep chosen labels out of its responses, though excluding files and email needs E5-level licensing. In GCC, Microsoft 365 Copilot and Purview's controls for it are listed as available.

## Slide 10 — Government cloud: GCC first, then the side notes

Purview differs a great deal between clouds, and changes often, so the book states availability feature by feature, as Microsoft Learn listed it on November 11, 2026. The baseline here is GCC. There, the core is listed as available: manual, mandatory and container labels, Rights Management and message encryption, D L P on every surface including Windows endpoints, auto-labeling, exact data match, and both audit tiers. A few gaps matter. The default label for a SharePoint library is still in development, and authentication contexts on labeled sites are on the engineering backlog. GCC High and DoD are side notes. Their clients need DNS records to reach the government Rights Management service, DoD doesn't list Advanced Message Encryption yet, and two Learn pages disagree on Insider Risk Management in GCC High. The rule for all of it: a license or cloud gap goes in a decision record, with a compensating control. It's a dependency, never a failed control.

## Slide 11 — Six roles run information protection

Information protection fails quietly when the person who decides is also the person who configures. The book uses six roles, by name, in every chapter. The policy owner, typically the C U I program manager, with the privacy official and the records officer, decides what the data is and how it must be handled. The platform owner, the Purview engineering lead, is accountable for the configuration and its baseline. The operator makes each change through change control. The security monitor triages alerts every day. The help desk answers users, and never removes a label or decrypts a file to close a ticket. And the assessor, the ISSO and the independent assessor, is accountable for the evidence package, while closure stays with the authorizing official. Three separations keep it honest. Owners decide and administrators configure. Super user recovery answers to the policy owner, because it reads content that owner governs. And in insider risk, no one both administers and investigates.

## Slide 12 — Roll out in rings, with a way back

Every control in the book follows the same path, and every step has a way back. Start with an inventory. Purview's content explorer exports where sensitive information types and labels already sit, one type at a time, so the rollout starts where the risk is. Treat it as a dated snapshot: counts can take up to seven days to update, and fourteen for SharePoint. Then a signed decision record, and the build, as code, in a test tenant first, because some label changes can't be cleanly undone. Then a pilot ring. For D L P, simulation is the pilot. It runs for up to fifteen days and keeps its data for thirty, so export the matches. It evaluates existing SharePoint and OneDrive content, but only new mail, Teams and device activity, so let those run through a business cycle. Then enforce ring by ring, and validate with a labeled sample. And rollback never means deleting a label, because content keeps it. You unpublish it instead.

## Slide 13 — Evidence an assessor can inspect

Everything ends in evidence an assessor can inspect. The baseline is one dated export of the labels, label policies, auto-labeling, D L P, audit status and the Rights Management configuration, taken monthly. Drift is any difference no change ticket explains, and drift that weakens a control on C U I goes to the authorizing official. The book carries three rows of the Zero Trust Assessment closure map, each with its minimum evidence. No labels, defaults or containers needs a policy export and a labeled sample. Rights Management and mail encryption need an encrypted test and the transport-rule export. Audit gaps need searchable synthetic events. And the metrics measure protection, not settings: the labeled share of sensitive content, container coverage of C U I sites, true-positive and override rates, and test passes. A policy that's on and catches nothing scores no better than one that's off. The package supports the controls it maps to; the assessor or authorizing official decides.

## Slide 14 — Decisions to make, and next steps

So, four decisions. Name the classes and their owners: a small register built from the C U I Registry, the Privacy Act and records schedules, with an outcome an assessor can test. Publish a small taxonomy with safe defaults: non-encrypting defaults, mandatory labeling, and three container labels. Keep a tested way back in: the super user feature off, recovery through an approved role, and a decryption test every quarter. And decide AI and evidence before rollout: which labels Copilot may process, what oversharing gets fixed first, and a monthly baseline the assessor can read. The next step needs no new tooling. Draft the class register and the decision records, run a dated inventory with what the tenant already licenses, and confirm each feature for your own cloud before planning on it. Protection has to travel with the data. Information Protection and Microsoft Purview has the detail, every claim footnoted. It's a draft, so check it again after the editor's review. Thank you.
