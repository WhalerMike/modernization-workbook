# Attribute-Driven Migration to Entra ID — deeper dive implementation, Part 2: groups, targeting and moving Group Policy

**Deck name: Attribute_Driven_Migration_Deeper_Dive_Part_2.** Part 2 of the three-part deeper dive implementation series, which goes below the two-part technical deep dive ([Part 1](../attribute-driven-migration-technical-part-1/README.md), [Part 2](../attribute-driven-migration-technical-part-2/README.md)) to the working detail an engineer runs: rule text, commands and parameters, the validation kit's input files, what a failing check says, and rollback. It follows the [Attribute-Driven Migration implementation guide](../../docs/project-plans/developer-workbooks/attribute-driven-migration/implementation-guide.md) and its [project plan](../../data/project-plans/attribute-driven-migration.yaml), and is built with the shared kit in [`../_build/`](../_build/README.md). This folder sits outside `docs/`, so the site doesn't render it.

The series is split by gate: Part 1 takes Gates 0–3, this part Gates 4–6, and Part 3 Gates 7–9. The core of this part is "adopt, don't build" for moving Group Policy, for devices (Book 05, Chapter 08) and servers (Chapter 09).

## Labels and sourcing

Every fact, command, rule and payload comes from a workbook chapter, a guide (`docs/books/guides/`), an evaluation (`docs/evaluations/`) or `examples/`; nothing is added from outside. Code on slides is copied from those sources: rule text from Book 03 Ch 10, Book 06 Ch 17 and Book 02 Ch 05; device writes, groups and filters from Book 05 Ch 08; `Backup-GPO` and `Set-GPLink` from Book 05 Ch 07; built-in definition names and GuestConfiguration requirements from Book 05 Ch 09; the kit run and input shapes from the validation kit's README and fixtures; `ca-export` from `examples/ms-automation`; the ownership assertion from `examples/ansible`. Codes such as `FIN-LED` are placeholders.

Design guidance is labeled: the one-owner and one-patch-owner rules, the `ConfigOwner` and `PatchOwner` tags, treating converted GPOs as drafts, the decisions and their options, and "What the overview simplified." Stages are labeled: VK-DG-03's rule evaluation and VK-INT-07's `groupPolicyMigrationReports` read are Microsoft Graph beta (VK-INT-07 runs only with `-IncludeBeta`); the `memberOf` rule is a preview ending November 3, 2026. The card management system writing `certificateUserIds` after AD is unverified, an open pilot in workbook issue #130, and Microsoft doesn't document Cloud Sync for that attribute. The kit's stated limits are carried too: VK-CA-01 reads the users condition only, so `ca-export` stays the record; VK-PIV-01 can't tell whether a value belongs to a current card, and whether Global Reader can read `authorizationInfo` is unconfirmed until a test-tenant run.
