# Decision Register {.unnumbered}

This register lists the decisions behind the workbook, from the repository's first pull request on, one entry each. Each entry gives the question, the options that were considered, the choice, the reason for it, its basis, its sources and the pages it shaped. The [Reviewers' Guide](reviewers-guide.md) explains how to check an entry and how to tell us you agree or disagree with it. Use the entry's ID when you do.

There are **131** workbook decisions: 128 settled, 0 challenged and 3 superseded. Below them are the **80** decision points the sample project plans leave to the agency that adopts them.

::: {.callout-note}
## How to read the basis
- **External requirement:** a federal requirement chose for us: a statute, an OMB memorandum, a CISA directive, a NIST publication or FedRAMP's rules. Disagree with the reading, not the requirement.
- **Microsoft Learn:** the choice follows Microsoft's own documentation for how the product works or should be configured.
- **Workbook design:** the workbook's own judgment. No source makes this choice, so it is the kind most open to argument.
:::

## Decision points in the sample project plans {#plan-decisions}

Each sample project plan names the decisions its project has to make, with the role that decides, the options and what happens if the decision is late. These are left to the agency that adopts the plan, so they have no choice here unless a workbook decision above settles the workbook's own default; that decision is named in the last column. Each plan's **Decision points** section has the decide-by week and float, and the plan's YAML in `data/project-plans/` is where each one is defined. IDs repeat across plans, so cite a plan decision with its plan, for example *Non-Person Identity Modernization, D-N2*.
