# Research gaps for the developer workbook *Building the Attribute-Driven Migration*

Five gaps were handed to the session that started this workbook. Each was researched on Microsoft Learn (MCP tools) or in the repository on October 30, 2026. Where a later chapter depends on one, the outline in `index.md` says so.

| # | Gap | Finding | Status | Source |
|---|---|---|---|---|
| 1 | GuestConfiguration cmdlets and parameters (Chapter 07) | `New-GuestConfigurationPackage`: `Name`, `Configuration` (compiled MOF path), `Path`, `Type` (`Audit` or `AuditAndSet`, default `Audit`), `FrequencyMinutes`, `FilesToInclude`, `Force`. `Protect-GuestConfigurationPackage`: `Path`, `Certificate` (Windows only), `PrivateGpgKeyPath` and `PublicGpgKeyPath` (Linux only); it needs a code signing certificate. `New-GuestConfigurationPolicy`: `PolicyId` (a GUID; reuse it to update), `ContentUri`, `DisplayName`, `Description`, `Parameter`, `PolicyVersion` (must increase on each release), `Path`, `Platform`; it sets `contentHash` itself. Learn's best practice is a version in the package name, because the assignment's `version` property applies only to Microsoft-hosted packages. Local testing, from an elevated PowerShell 7 session (`sudo pwsh` on Linux): `Get-GuestConfigurationPackageComplianceStatus` (`Path`, `Parameter`) checks the package and reports compliance, installing the machine configuration agent locally on first run; `Start-GuestConfigurationPackageRemediation -Path` runs `Set` for an `AuditAndSet` package and changes the local machine. The module installs on Windows and Ubuntu 20 or later, needs PowerShell 7.1.3 (Windows) or 7.2.4 (Ubuntu), and applying configurations needs the Azure VM guest configuration extension 1.26.24 or Arc agent 1.10.0 or later. | resolved | Learn, "How to create custom machine configuration package artifacts"; "How to test machine configuration package artifacts"; "How to sign machine configuration packages"; "How to create custom machine configuration policy definitions"; "How to set up a machine configuration authoring environment" |
| 2 | A dynamic-rule clause that excludes agents' user accounts (Chapter 04) | Learn says an agent's user account is a subtype of user, is evaluated by user-based rules, isn't distinguished by default, and can be excluded "by including a condition in the membership rule"; rules can also include only agents' user accounts or target one agent identity blueprint. Agent identities (service principals) can't be members of dynamic groups. Learn's property tables don't name the property to use. No `user.isAgent`-style property was found in searches. | open: Chapter 04 waits for Learn to document the property; don't guess one | Learn, "Manage rules for dynamic membership groups in Microsoft Entra ID" (Overview and property tables); "The agent's user account in Microsoft Entra Agent ID" |
| 3 | Commands to set Entra Connect's soft-match and hard-match blocking | `Connect-MgGraph -Scopes "OnPremDirectorySynchronization.ReadWrite.All"`, then `Get-MgDirectoryOnPremiseSynchronization`, set `Features.BlockSoftMatchEnabled` or `Features.BlockCloudObjectTakeoverThroughHardMatchEnabled` to `$true`, and `Update-MgDirectoryOnPremiseSynchronization -OnPremisesDirectorySynchronizationId $id -Features $features`. Entra PowerShell: `Set-EntraDirSyncFeature -Features 'BlockSoftMatch' -Enable $true` (Global Administrator). The read, `GET /directory/onPremisesSynchronization`, is delegated only with Global Administrator as the only role. From July 1, 2026, Entra ID also blocks hard match to privileged, privileged-eligible or already-mapped cloud accounts. | resolved; built into Chapter 03 as VK-SYNC-02 | Learn, "Configure Microsoft Entra Connect for an existing tenant"; "Get onPremisesDirectorySynchronization"; "Set-EntraDirSyncFeature" |
| 4 | Book 03's worker-type rule patterns lack the `userType` guard | Confirmed: `docs/books/b03-hr-identity/10-from-attributes-to-access.md`, the "Organization and worker type" and "Exclusion" rows of the rule pattern table (lines 47–48 on October 30, 2026), use `user.accountEnabled` but not `user.userType -eq "Member"`. VK-DG-01 already flags such rules. Learn's members-only pattern is `(user.objectId -ne null) -and (user.userType -eq "Member")`. | resolved: both rows now carry the guard (same pull request; logged in Book 03's Chapter 10 verification file) | Book 03, Chapter 10; Learn, "Manage rules for dynamic membership groups" |
| 5 | Sample `patch_owner` data in `examples/ansible/inventory/sample/cmdb_export.csv` | Confirmed missing: the sample's columns end at `patch_group`; the Ansible guide's rule 5 names `patch_owner`, mirrored to the Arc `PatchOwner` tag. | open: Chapter 08 adds the column with tests before relying on it | `examples/ansible/inventory/sample/cmdb_export.csv`; Ansible guide, rule 5 |

Two conflicts found on Learn while writing Chapter 01, recorded here so a later edit doesn't "fix" the code to the looser figure:

- The `/bulkUpload` rate limit is 40 requests per second on the API reference page and 40 calls per 5 seconds on the concepts and troubleshooting pages. The code paces to the stricter.
- The concepts page names `ProvisioningLog.Read.All` for API clients reading provisioning logs; the List provisioningObjectSummary page names `AuditLog.Read.All` and `Directory.Read.All` as least privileged.
