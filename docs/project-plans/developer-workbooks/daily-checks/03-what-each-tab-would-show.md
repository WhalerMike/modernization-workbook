## Goal and audience

**Goal.** By the end of this chapter you can show, without a tenant, what each tab would display on a given morning; tell an operator which tabs can't be trusted because their source has gone quiet; and prove each tab's tables answer in a real workspace.

**Audience.** Developers, security operations, and the operators who read the workbook each morning.

## Start with Microsoft's documentation

### What Microsoft gives you

Book 15, Chapter 12's [telemetry-completeness check](../../../books/b15-day2-operations/12-the-day-two-runbook.md#the-telemetry-completeness-check) lists each expected table past its freshness limit, using `union isfuzzy=true` so a missing table shows as a null rather than failing the query. Sentinel's health page gives the `SentinelHealth` query for each connector's latest failure, and recommends Azure Monitor alert rules for health drifts.[^dc03-health] Intune's diagnostic settings export compliance once every 24 hours, and it "can take up to 48 hours" to arrive; Microsoft says not to "rely on a fixed or previously observed completion time."[^dc03-intune] `az monitor log-analytics query` runs a KQL query against a workspace by its GUID; it comes from the Azure CLI's `log-analytics` extension.[^dc03-cli] Learn's "Unavailable computers" query takes each computer's latest `Heartbeat`.[^dc03-heartbeat] `repadmin /showrepl * /csv` reports each replication link's last success, last failure and last failure status, and reading it forest-wide needs Enterprise Admins or equivalent; the Logs Ingestion API takes a JSON array posted to the data collection rule's stream.[^dc03-repadmin][^dc03-ingest]

### What it leaves to you

Each row is pinned by a test in the `Chapter 03` block of `tests/DailyChecks.Tests.ps1`, or in `deploy/tests`.

| Learn's material, as published | Why it matters | What the kit adds |
|---|---|---|
| The completeness query lists dark tables | The other tabs don't know their table is dark | Each tab's render rule names its sources and freshness limits; a stale source makes the tab STALE, never CLEAR |
| A query result is rows or no rows | No rows can mean "nothing to do" or "no data" | `emptyMeans`: an empty probe result is NO DATA; an empty risk queue over fresh sources is CLEAR |
| Intune's timing is variable | A day-old export read as live | The devices tab's limit is 48 hours |
| A screenshot is easy to file | The picture goes into the package | The render carries the banner, and `Write-DcEvidence` refuses it |
| No reachability check | Nobody proves each tab's tables answer | `Test-DcReachability`: newest record and count per table, Delivering, Late or Missing |
| "Unavailable computers" lists computers that did report, then stopped | A server that never reported, or was dropped from the collection rule, isn't on the list at all | The sync and Active Directory tabs start from the settings' server lists, one row each, and flag an empty heartbeat |
| `repadmin` output is a CSV in local time on one host | It isn't in the workspace, and a script that copies it to a share is the ungoverned shape task 7 rules out | `Invoke-DcReplicationProbe`: one record per link with a verdict, times in UTC, sent with `-Send` to `DcReplicationProbe_CL` |

## The code

### The render rules

Each workbook tab's `render` rule in the manifest has `freshness` (source table to limit in minutes), `emptyMeans` (`clear` or `no-data`) and `flag` (the rows that need work: `any`, `eq` a value, or `older-than-column` for the telemetry rows). `Get-DcRender` reads one fixture file per tab (what the tab's queries would return, and when each source last delivered) and decides, in order:

1. a link-out tab shows **LINK-OUT**;
2. no result shows **NO DATA**;
3. any source past its limit shows **STALE**, and says the rows shown may be incomplete;
4. any flagged row shows **ATTENTION**;
5. no rows where a row is expected shows **NO DATA**;
6. otherwise **CLEAR**.

Rows can carry their own limit: the sync and Active Directory tabs' per-server rows have `HeartbeatLimitMin` (60) and, for the synchronization servers, `BackupLimitMin` (1,560, a night's backup plus two hours), and `older-than-column` flags an empty or old time, so a server that stopped sending is ATTENTION, never quiet.

`Invoke-DcRender.ps1` writes `render.json` and `render.md`, both with the banner, and a manifest marked `notEvidence`. The output depends only on `-AsOf` and the fixtures: a test renders twice, once under another culture, and compares the hashes.

### The reachability check

`Test-DcReachability` sends, for each table any tab reads, `<table> | where TimeGenerated > ago(3d) | summarize LastSeen = max(TimeGenerated), Records = count()` with `az monitor log-analytics query`, and compares the age with the table's limit. It reads only. `-FixturePath` reads saved answers instead, as Lab 1 does.

### The replication probe

`ConvertFrom-DcRepadminCsv` reads `repadmin /showrepl * /csv` and writes one record per link: `DestinationDc`, `SourceDc`, `NamingContext`, `Failures`, `LastSuccessUtc`, `LastFailureUtc`, `LastFailureStatus` and `Verdict` (`failing` when the last status isn't 0). `repadmin` prints the host's local time; `-TimeZoneId` names the zone and the records carry UTC. `Invoke-DcReplicationProbe.ps1` runs it, writes `probe.json` and a hashed manifest (task `probe`), exits 1 if any link fails, and with `-Send` posts the records with `az rest` to the data collection rule's stream, `api-version=2023-01-01`, token audience `https://monitor.azure.com`. It reads the directory and changes nothing; Chapter 04 says where it runs.

## Dangers

| Danger | What happens | The guard |
|---|---|---|
| A missing connector looks healthy | Empty risk and emergency access queues on a morning SigninLogs stopped | STALE over a stale source; the telemetry tab first |
| A missed probe shows yesterday's green verdict | The operator reads "compliant" from a run that didn't happen today | The sync tab's 24-hour limit makes it STALE |
| A render filed as evidence | A picture stands in for the checks' records | `Write-DcEvidence` refuses it |
| A silent server read as a quiet one | No rows from a domain controller that stopped sending | One row per server from the settings, flagged on an old or empty heartbeat |
| A Tier 0 probe run from a lower tier | Enterprise Admins credentials on an ordinary server | Chapter 04: the probe runs only on a Tier 0 host, or not at all |
| A reachability check with write rights | A reader role grows into contributor | Log Analytics Reader only; the check sends only queries |

- [ ] No render or screenshot is in the evidence package.
