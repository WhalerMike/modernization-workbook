# Chapter 04 — Labels, Policies and Containers

*A label is a promise about who can open the content. When the rights quietly grow by one person, the label still says the same thing on the screen.*

::: {.callout-note}
## In this chapter
The code behind the guide's [G2 The label taxonomy](../../../books/guides/information-protection-implementation.md#step-2-the-label-taxonomy), [G3 Publication and defaults](../../../books/guides/information-protection-implementation.md#step-3-publication-and-defaults) and [G4 Container labels](../../../books/guides/information-protection-implementation.md#step-4-container-labels). The guide's pass is "the export matches the design table"; you read how `Invoke-IpLabels` makes that comparison line by line from `labels.json` and `label-policies.json`. Lab 1 finds four faults in the fixtures; Lab 2 compares a test tenant with its plan.
:::

## Goal and audience

For the developer who owns the label checks, and the platform owner who keeps the plan. By the end you can say, label by label and policy by policy, where the tenant differs from [Book 20, Chapter 02's taxonomy](../../../books/b20-information-protection/02-sensitivity-label-architecture.md#b20-02-the-taxonomy-from-classes-to-labels) and [publishing table](../../../books/b20-information-protection/02-sensitivity-label-architecture.md#b20-02-publishing-policies).

## Start with the guide's Validate step

### What the guide gives you

G2 lists `Get-Label` by priority and saves it; G3 lists `Get-LabelPolicy` with its labels, scope, exclusions and `Settings`. Both passes are a comparison with the design: one row per designed label, in order, no extra label; each policy's labels, scope, exclusion group and default settings as designed.

### What it leaves to you

- **The design as data.** The plan's `labels` and `labelPolicies` hold the design table.
- **Rights holders.** A label's `EncryptionRightsDefinitions` is `identity:RIGHTS;identity:RIGHTS`.[^ip04-newlabel] The check compares the identities, so a person added beside the holders group fails, as Book 20 says rights go to groups or the domain, never individuals.[^ip04-b20]
- **GUIDs in settings.** A policy's default label settings (`defaultlabelid`, `outlookdefaultlabel`, `teamworkdefaultlabelid`) carry a label GUID, not its name, as [Book 20, Chapter 03](../../../books/b20-information-protection/03-label-publication-and-defaults.md#b20-03-enforcement) sets them. The check resolves names to GUIDs from the same export.

## The code

`Invoke-IpLabels` reads the plan and the snapshot and writes one row per check:

- `LBL-nn` per planned label: exists (by name, display name or GUID); `encryption` on or off; `header` text; `rightsTo` identities; and any `properties` the plan names (for a container label, for example `SiteAndGroupProtectionAllowAccessToGuestUsers`), compared as written.
- `LBL-EXTRA`: a label in the tenant the plan doesn't have fails, with Book 20's rule in the message: unpublish it or add it to the plan with a decision record, never delete it.
- `LBL-ORDER`: the planned priorities are in the same order in the tenant.
- `POL-nn` per planned policy: its labels (missing and extra), its scope (`ExchangeLocation`), its exclusion group, and each planned setting.
- `POL-ORDER`: the policies' priorities are in the planned order.

`labels.csv` keeps the label table with each label's findings. Tag `ch04` covers the four faults and the GUID resolution.

::: {.callout-warning}

## Verified facts

| Item | Value | Source |
|---|---|---|
| Rights format | `EncryptionRightsDefinitions` grants rights to users, mail-enabled groups or domains as `identity:rights` | [^ip04-newlabel] |
| Who gets rights | Mail-enabled groups, Microsoft 365 groups or the tenant's domain; never individuals (program design) | [^ip04-b20] |
| Default and mandatory settings | Set per policy with `Set-LabelPolicy -AdvancedSettings`; the default label by GUID | [^ip04-policy] |
| Labels and policies in GCC | Manual and mandatory labels, and labels for groups and sites, Available | [^ip04-gcc] |

## Dangers

| Danger | Mitigation |
|---|---|
| Deleting a label to clear `LBL-EXTRA` | Unpublish it or add it to the plan; content keeps the label's meaning |
| A container label's group settings changed after publishing | Not applied to groups that already carry it ([Book 12, Chapter 09](../../../books/b12-security-operations/09-data-protection-and-classification.md#labels-on-teams-groups-and-sites)); plan a new label |
| The plan copied from the tenant | Then it passes by definition; fill it from the design table and the decision records |
