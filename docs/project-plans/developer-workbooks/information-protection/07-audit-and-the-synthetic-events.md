# Chapter 07 — Audit and the Synthetic Events

*An audit setting says the log is on. A synthetic event, found where it should be and in time, says the log works.*

::: {.callout-note}
## In this chapter
The code behind the guide's [G10 Audit, insider risk and communication compliance](../../../books/guides/information-protection-implementation.md#step-10-audit-insider-risk-and-communication-compliance), its audit check for [G11](../../../books/guides/information-protection-implementation.md#step-11-ai-data-security), and the guide's [synthetic events](../../../books/guides/information-protection-implementation.md#synthetic-events), which are the minimum evidence for Book 20's part of closure-map row CM-14. You read how `Search-IpSyntheticEvents` records the search with its test, and how `Invoke-IpAudit` checks ingestion, retention and timing. Lab 1 finds one late event; Lab 2 runs the test in a test tenant.
:::

## Goal and audience

For the developer who owns the audit checks and the operator who runs the quarterly synthetic tests. By the end you can show, for one test, what was done, when the search ran, which events it found and how long each took to appear.

## Start with the guide's Validate step

### What the guide gives you

G10 reads `Get-AdminAuditLogConfig` in Exchange Online PowerShell (in Security & Compliance PowerShell the property always reads `False`), lists `Get-UnifiedAuditLogRetentionPolicy`, and searches the test user's label events of the last four hours. G11 searches `CopilotInteraction`. [Book 20, Chapter 10](../../../books/b20-information-protection/10-audit-insider-risk-and-communication-compliance.md#how-turn-on-retain-and-test-purview-audit) gives the test: as the test user, in Office for the web, apply a label to a test document and then remove it.

### What it leaves to you

- **When the test started.** Without it, "found" says nothing about delay. Learn gives no guaranteed latency for audit search;[^ip07-search] the plan sets the program's target (`audit.synthetic.withinHours`, four hours in the fixtures).
- **One record.** The search, the operations expected, the start time and the events, in one file the evidence record can hash.

## The code

`Search-IpSyntheticEvents.ps1` connects to Exchange Online PowerShell through the runner (Chapter 02), runs `Search-UnifiedAuditLog` for the test user and the plan's operations from the test's start to now, disconnects, and writes `startedAt`, `searchedAt`, `user`, `operations` and the events (time, user, operation, record type) to one JSON file.

`Invoke-IpAudit` writes:

- `AUD-01` ingestion on, from `audit-status.json`; a `False` fails with the reason to read it in Exchange Online PowerShell.
- `RET-nn` each retention policy the plan names, with its duration.
- `SYN-nn` each expected operation: found, and how many hours after the start; later than the target fails. With no search given, `SYN-00` is `Info`.

`synthetic.csv` keeps the timing; the search file is copied into the run folder. Tag `ch07` covers ingestion off, the late event and the search record.

::: {.callout-warning}
## Illustrative code
Lab 1 reads fictional fixtures. The kit searches only the test user's events. It doesn't route audit data to the log platform; [Book 12, Chapter 04](../../../books/b12-security-operations/04-platform-and-m365-telemetry.md) does, and the guide's pass also asks that the events be found there.
:::

## Lab 2: a test tenant

Use a test tenant, never production, with a test user licensed for Office for the web and a test document in a test site. The operator account needs View-Only Audit Logs or Audit Logs. Work in `examples/information-protection`. You'll replace `<settings-file>`, `<output-folder>`, `<test-user-upn>` and `<test-started-at>` (the UTC time you start the test, as `yyyy-MM-ddTHH:mm:ssZ`).

<!-- labs:begin lab-2-commands (generated by scripts/generate_labs.py; not part of the reviewed page) -->

::: {.callout-note #lab-2-commands collapse="false" title="Every command in Lab 2"}
Every command in this lab, in order, from `examples/information-protection`. Each step below says what it does and what to look for.

```powershell
# Step 1: After an hour or more, search for it
./Search-IpSyntheticEvents.ps1 -SettingsPath <settings-file> -UserId <test-user-upn> -StartedAt <test-started-at> -OutputPath <output-folder>/synthetic.json

# Step 2: Export and check
./Export-IpBaseline.ps1 -SettingsPath <settings-file> -OutputPath <output-folder>/snapshot
./Invoke-IpAudit.ps1 -SettingsPath <settings-file> -SnapshotPath <output-folder>/snapshot -SyntheticPath <output-folder>/synthetic.json -OutputPath <output-folder>/audit

# Step 3: Back it out
Remove-Item -Recurse -Force <output-folder>
```

:::

<!-- labs:end -->

First run the test itself, in the browser: as `<test-user-upn>`, in Office for the web, open the test document, apply a label, save, remove the label and save. Note the time you started as `<test-started-at>`. Then:

1. **After an hour or more, search for it:**

   ```powershell
   ./Search-IpSyntheticEvents.ps1 -SettingsPath <settings-file> -UserId <test-user-upn> -StartedAt <test-started-at> -OutputPath <output-folder>/synthetic.json
   ```

2. **Export and check:**

   ```powershell
   ./Export-IpBaseline.ps1 -SettingsPath <settings-file> -OutputPath <output-folder>/snapshot
   ./Invoke-IpAudit.ps1 -SettingsPath <settings-file> -SnapshotPath <output-folder>/snapshot -SyntheticPath <output-folder>/synthetic.json -OutputPath <output-folder>/audit
   ```

   A `SYN` row that fails as "not found" may only be late: search again later before you treat it as a gap.

3. **Back it out.** The label was removed in the test; nothing else changed. Keep the folder as the test record or delete it:

   ```powershell
   Remove-Item -Recurse -Force <output-folder>
   ```

## Verified facts

| Item | Value | Source |
|---|---|---|
| Where to read audit status | Exchange Online PowerShell; always `False` in Security & Compliance PowerShell | [^ip07-on] |
| Label events | Office for the web records `FileSensitivityLabelApplied` and `FileSensitivityLabelRemoved`; desktop apps `SensitivityLabelApplied` and `SensitivityLabelRemoved` | [^ip07-ops] |
| Copilot events | `CopilotInteraction` | [^ip07-ops] |
| Search latency | No guaranteed latency | [^ip07-search] |
| Search roles | View-Only Audit Logs or Audit Logs | [^ip07-bp] |
| Audit in GCC | Audit (Standard) and Audit (Premium), with one-year and ten-year retention, Available; audit search enhancements on engineering backlog | [^ip07-gcc] |

## Dangers

| Danger | Mitigation |
|---|---|
| Audit "fixed" because it read `False` in the wrong shell | The export reads it in Exchange Online PowerShell |
| A late event treated as missing | Search again before you record a gap; record the timing either way |
| The test user's events read as anything but a test | The search names one test user and a start time |
