# Chapter 05 — Rights Management and Message Encryption

*The recovery procedure ends by turning the super user feature off. The check is there for the day someone forgets the last step.*

::: {.callout-note}
## In this chapter
The code behind the guide's [G5 Rights Management and recovery](../../../books/guides/information-protection-implementation.md#step-5-rights-management-and-recovery), [G6 Message encryption](../../../books/guides/information-protection-implementation.md#step-6-message-encryption) and the co-authoring setting of [G7](../../../books/guides/information-protection-implementation.md#step-7-sharepoint-and-onedrive). You read how `Invoke-IpProtection` reads `aipservice-configuration.json`, `irm-configuration.json`, `ome-configuration.json`, `transport-rules.json` and `policy-config.json` against the plan. Lab 1 finds four faults; Lab 2 checks a test tenant, including the state just after a rehearsed recovery.
:::

## Goal and audience

For the developer who owns the protection checks and the platform owner who runs recovery. By the end you can say whether anyone can decrypt everything right now, and whether each approved message scenario encrypts as designed.

## Start with the guide's Validate steps

### What the guide gives you

G5: `Get-AipService`, `Get-AipServiceSuperUserFeature` and `Get-AipServiceSuperUser`, passing on `Enabled`, `Disabled` and none listed. G6: `Get-IRMConfiguration`, `Test-IRMConfiguration` and `Get-TransportRule`, passing on `AzureRMSLicensingEnabled` `True`, `OVERALL RESULT: PASS` and each scenario's rule enabled and enforcing. G7: `Get-PolicyConfig`, passing on `EnableLabelCoauth` `True`.

### What it leaves to you

- **One read for the super user state.** `Get-AipServiceConfiguration` returns `SuperUsersEnabled` and `SuperUsers` with the rest of the configuration;[^ip05-aip] the export already holds it.
- **What each rule should be.** The plan gives each mail flow rule a stage (`audit`, `enforce`, `retired`) and its template, as [Book 20, Chapter 06](../../../books/b20-information-protection/06-exchange-message-encryption.md#how-verify-brand-and-stage-message-encryption) stages them: a rule starts in `Audit` mode and moves to `Enforce`.
- **`Test-IRMConfiguration` stays manual.** It sends a test between two mailboxes; it isn't a read of configuration, so the kit leaves it to the guide's G6 step.

## The code

`Invoke-IpProtection` writes:

- `RMS-01` the service's `FunctionalState`; `RMS-02` the super user feature matches the plan (`Disabled` at rest); `RMS-03` no standing super users. With the Rights Management read off, `RMS-01` is an `Info` row that says to run G5 by hand.
- `IRM-01` the IRM settings the plan names; `OME-nn` each message encryption configuration's planned properties (for example `OTPEnabled` true and `SocialIdSignIn` false).
- `MFR-nn` each planned rule: `State` and `Mode` for its stage (`audit` is enabled in `Audit` or `AuditAndNotify`; `enforce` is enabled in `Enforce`; `retired` is disabled) and the template it applies.
- `COA-01` co-authoring.

`mail-flow-rules.csv` keeps the rule table. Tag `ch05` covers the faults and the case where Rights Management wasn't read.

::: {.callout-warning}

## Verified facts

| Item | Value | Source |
|---|---|---|
| Super user state | `Get-AipServiceConfiguration` returns `SuperUsersEnabled` and `SuperUsers` | [^ip05-aip] |
| Super user feature | Enable as needed; disabling doesn't remove users from the super user list, so the procedure removes them too | [^ip05-su] |
| Message Encryption in GCC | Message Encryption and Advanced Message Encryption Available; mail flow rules available in Exchange Online for GCC | [^ip05-gcc] |
| Mail flow rule test modes | `Audit` and `AuditAndNotify` test a rule; `Enforce` acts | [^ip05-rules] |
| Co-authoring | `Get-PolicyConfig`, `EnableLabelCoauth` | [^ip05-coauth] |

## Dangers

| Danger | Mitigation |
|---|---|
| The super user feature left on after a recovery | `RMS-02` and `RMS-03`; drift raises it to P1 (Chapter 08) |
| A rule left in `Audit` after its ring | `MFR` rows by stage |
| Treating `RMS-01` `Info` as a pass | It means the read was off: run G5 by hand |
