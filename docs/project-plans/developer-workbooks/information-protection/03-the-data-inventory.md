# Chapter 03 — The Data Inventory

*A class nobody owns, or one the tenant has no way to find, is a label waiting to be applied to nothing.*

::: {.callout-note}
## In this chapter
The code behind the inventory in the guide's [G1 Classes, decisions and inventory](../../../books/guides/information-protection-implementation.md#step-1-classes-decisions-and-inventory). [Book 20, Chapter 01](../../../books/b20-information-protection/01-data-inventory-and-classification.md#b20-01-inventory-find-where-the-data-already-is) exports the type catalog and pages through content explorer one type at a time. You read how `Invoke-IpInventory` checks the class register against the catalog and summarizes the counts the export took. Lab 1 finds the fixtures' two faults; Lab 2 counts a test tenant.
:::

## Goal and audience

For the developer who supports the policy owners' class register. By the end you can say, for each class, whether it has an owner and a label, whether every type that finds it exists in the tenant, and how much content those types find in Exchange, OneDrive and SharePoint.

## Start with the guide's Validate step

### What the guide gives you

G1's Validate exports `Get-DlpSensitiveInformationType` to a CSV and counts one type in one workload with `Export-ContentExplorerData`; the pass is that every type the register names is in the catalog and a count returns for each. [Chapter 01's paging loop](../../../books/b20-information-protection/01-data-inventory-and-classification.md#b20-01-inventory-find-where-the-data-already-is) exports the items themselves.

### What it leaves to you

- **The register as data.** The class register is a document; the check needs it as rows.
- **Counts, not items.** The rollout needs to know where to start, not every file name. The kit keeps `TotalCount` per type and workload, and leaves the item export to Chapter 01 when an owner asks for it.
- **GCC.** Content explorer is available in GCC; Teams data in content explorer is in development ([the guide's table](../../../books/guides/information-protection-implementation.md#government-cloud-availability)), so the counts cover Exchange, OneDrive and SharePoint.

## The code

`templates/class-register.csv` has four columns: `class`, `owner` (a role), `label`, and `sits` (the type names, separated by `;`). With `reads.inventory` on, the export (Chapter 02) counts each type the catalog has, in each workload.

`Invoke-IpInventory` writes one `INV-nn` row per class:

- **Fail** when the class has no owner or no label, or names a type that isn't in the tenant's catalog (a misspelling, a type never imported, a type for another cloud).
- **Warn** when the class names no type: it is labeled by default or by hand, not found by detection, which is a decision for the owner to record.
- **Pass** otherwise, with the total and the count per workload.

`inventory.csv` keeps one row per class, type and workload. Tag `ch03` in `tests/Kit.Tests.ps1` checks the two faults and the counts.

## Dangers

| Danger | Mitigation |
|---|---|
| A misspelled type in the register silently finds nothing | `INV` fails on a type the catalog doesn't have |
| Counts read as a census | They're a dated snapshot of what had been classified; say so in the record |
| Content viewer granted to read counts | Counts need only the List viewer role; Content viewer shows the items themselves |
