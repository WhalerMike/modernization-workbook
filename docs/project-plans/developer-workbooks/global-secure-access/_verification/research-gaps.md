# Research gaps for the developer workbook *Building Global Secure Access*

Found while building the kit and writing the chapters, November 17, 2026. Each was researched on Microsoft Learn's Graph reference pages (WebFetch) or in the repository. None conflicts with the guide's text: each is either a less-privileged permission Learn lists beside the guide's, or something Learn doesn't state.

| # | Gap | Finding | Status | Source |
|---|---|---|---|---|
| 1 | Least-privileged permissions for Step 1's reads (Chapter 01) | The guide's Step 1.1 connects with `Organization.Read.All` and `NetworkAccess.Read.All`. Learn's tables name `LicenseAssignment.Read.All` for `subscribedSkus` (with `Organization.Read.All` as higher privileged) and `NetworkAccessPolicy.Read.All` for `tenantStatus` and `getDeviceUsageSummary`, delegated only. Whether `NetworkAccess.Read.All` also serves those two reads isn't stated. | recorded: the kit asks for Learn's least-privileged permissions; the guide's connect line could add them at its next revision (owner's decision) | Learn, List subscribedSkus; Get tenantStatus; reports: getDeviceUsageSummary |
| 2 | `trafficType` on `getDeviceUsageSummary` (Chapter 03) | The page's parameter table marks `trafficType` required (`microsoft365`, `private`, `internet`); its own example request and the guide's Step 3 Validate omit it. | open: the kit sends the guide's request; Lab 2 step 4 records whether the service needs the parameter | Learn, reports: getDeviceUsageSummary |
| 3 | Two reads without a verified Learn page (Chapters 02, 05, 06) | `GET /policies/crossTenantAccessPolicy/partners` (the guide's Step 8.1) wasn't read for the kit. No page read gives a request that lists Private Access applications with their segments and assignments, or its permission. | open: both calls are marked unverified and need `-AllowUnverified`; Lab 2 compares their results with the portal | Learn, Configure Microsoft Entra Private Access using Microsoft Graph APIs |
| 4 | The DNS-over-HTTPS policy value (Chapter 03) | The device script reads `DnsOverHttpsMode` under the Edge and Chrome policy keys and expects `off`, the Chromium policy value for Disabled; Learn's client page names the Intune setting, not the registry value. | open: Lab 2 step 1 records the value on a device with the profile | Learn, Install the Global Secure Access client for Windows |
| 5 | `TlsStatus` values (Chapter 07) | Carried from the guide: Learn's TLS concept page lists Success and Failure; its operations page filters on `Inspected`. | open, as in the guide | guide's What couldn't be verified |
| 6 | Reading TLS inspection by Graph (Chapter 07) | No Graph request for TLS inspection policies or certificates was verified for the kit, so the TLS record is the platform owner's export from the portal. | open: replace `inputs/tls.json` with a declared read once a Learn page gives it | — |
| 7 | Profile assignments by Graph (Chapters 04, 09) | Carried from the guide: the pages read give a portal procedure only. | open, as in the guide; the plan lists the step as manual | guide's What couldn't be verified |
| 8 | Microsoft samples to pin (all chapters) | The Privileged Access brief pins Microsoft's samples under `examples/third_party`. For Global Secure Access the only Microsoft code read is the requests on the Graph tutorial pages, which the guide quotes; no sample repository was found. | recorded: nothing pinned; the kit cites the tutorial pages | — |
