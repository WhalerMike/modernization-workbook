## Rules

- Front matter as in Chapter 01, including `family: dw-non-person-identity` and `review-status: pending`. Never set `approved` yourself: the owner approves a page with `python scripts/source_watch/review_gate.py --approve <page>`. Any change to an approved page sends it back to the weekly review list.
- No "Book NN" in this workbook's own name or title. No narrated chapter tour until the chapter is approved.
- **Microsoft Learn first, and as much of it as possible.** For anything about a Microsoft product, API, cmdlet, permission, limit or procedure, cite Microsoft Learn (learn.microsoft.com), found with the Microsoft Learn MCP tools. Prefer Learn's own procedures, commands and code samples over writing new ones, and follow Learn's wording for names and limits. Use a non-Learn source only when Learn has nothing, say so in the verification log, and replace it once Learn covers the point. When two Learn pages disagree, cite both and follow the stricter.
- **Microsoft's own samples before our code.** When Microsoft publishes a sample for the task (Learn pages and tutorials, `microsoftgraph/*`, `Azure-Samples/*`), start the chapter from it, run it offline against fakes in Lab 1 (never against a real tenant or domain), and build our code only for what it leaves out, with a table of the gaps and tests that pin them. Keep a pinned, unmodified copy under `examples/third_party/<name>/` with `snapshot.json` (upstream repository, path, commit, dates, license, per-file SHA-256, checked against the upstream git blob hashes) and `SNAPSHOT.md`, add a `github_commits` feed per upstream path to `data/source-watch/feeds.json` with `"books": ["DW"]` and a unique `id`, and update the copy only in a reviewed pull request. When the sample lives only inside a Learn page, pin the page's source from `MicrosoftDocs/*` or `microsoftgraph/microsoft-graph-docs-contrib`. Link Learn pages; don't copy their text.
- **The estate.** Microsoft 365 GCC (Moderate) with commercial Azure: `login.microsoftonline.com`, `graph.microsoft.com`, `management.azure.com`. GCC High and DoD have separate hosts. On-premises Active Directory exists until the program's G5. Say so where endpoints matter, and give each feature's US Government availability and its release stage (preview or beta) from Learn. Code takes an explicit cloud name and has no default.
- **Least privilege per call.** Every call (Graph, Resource Manager, or an Active Directory cmdlet) is declared in `examples/non-person-identity/config/calls.json` with its least-privileged permission, Azure role or AD right and the Learn page that states it, and each task declares its permissions; a test keeps each task's declaration equal to the union of its calls. Reads use GET and Get-AD* only; writes are a separate task with a writer, a dry run, an approved plan hash and `-Apply`.
- **Never delete.** The orphan rule disables; retirement goes through the plan's reviewed decommission process, never through this code.
- Every new external claim cites Microsoft Learn (or a workbook chapter) with an access date. Footnote keys are unique in this workbook: `[^npNN-key]` in Chapter NN, `[^npi-key]` on the index.
- Label the program's own positions *Design guidance*. Give every preview or beta feature its stage.
- Never name an agency. Use the fictional `contoso.example` tenant (initial domain `contosoexample.onmicrosoft.com`) and AD domain `corp.contoso.example` in fixtures, documentation IP ranges, and invented object IDs. No personal data in any web request.
- Code changes come with tests in the example's own suite (Pester 5 under `pwsh`). One module per chapter under `examples/non-person-identity/powershell/` (`Npi` prefix), sharing `NpiCore`. If a chapter touches `examples/validation-kit`, keep the change additive: new check files and new catalog entries.
- Keep LF line endings in new files; keep an existing file's line endings when you edit it.
- Each chapter keeps `_verification/<file-stem>.md`: a claims log and a carry-forward ledger. Open research questions go in `_verification/research-gaps.md`, **in the chapter's own block of row numbers** (the table above), so chapters written in parallel don't collide. Leave unused numbers unused.
