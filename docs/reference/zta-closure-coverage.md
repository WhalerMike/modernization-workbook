# Zero Trust Closure Coverage {.unnumbered}

Zero Trust assessments of Microsoft cloud tenants keep raising the same families of finding: emergency access, standing privilege, Conditional Access gaps, application secrets, device compliance, labels and encryption, skipped tests. In November 2026 the workbook's owner turned those families into an anonymized update plan for the workbook: eight global conventions, line-by-line additions to existing books, a new book on information protection, three engineering guides, and a closure map from each finding family to the books and guides that carry it. This page tracks that plan, item by item.

::: {.callout-important}
## Guidance coverage, not implementation
This page says which workbook pages give guidance for each item. It says nothing about any organization's tenant. A row marked **Implemented** means the workbook now carries the guidance; it doesn't mean any agency has built the control, and it never means a control or finding is closed. Whether an organization has done the work is shown by its own evidence, in the five control states of [Book 00, Appendix D](../books/b00-orientation/appendix-d-control-states-and-evidence.md#control-states), and whether a finding is closed is its authorizing official's or assessor's decision. The plan holds no agency name, tenant, person, application, count or identifier from any assessment, and neither does this page.
:::

## How to read it

- **ID** is the instruction's own ID. G-01 to G-08 are the global conventions; B02-01 to B18-02 are additions to existing books; B20-01 to B20-12 are the chapters of the planned twentieth book, Information Protection & Microsoft Purview (the plan numbers it nineteenth; the workbook's Book 19 already exists); GSA, XDR and AZS items are sections of three implementation guides; CM-01 to CM-15 are the closure-map rows; ZTA-GUIDE is the Zero Trust Assessment tool guide.
- **Wave** is the plan's priority, 1 to 4: privileged identity, Conditional Access, application credentials, devices, auditing and assessment evidence first; then information protection; then Zero Trust network access; then Defender XDR and Azure security.
- **Status** is the workbook's guidance: **Implemented** (the pages carry it), **Partial** (some of it, or defined but not yet applied everywhere), **Planned**, **Deferred** (with a reason), or **Not applicable** (with a reason). macOS hardening is not applicable because macOS and Linux are outside the workbook's scope.
- **Where** links the pages that carry the item; **PR** is the pull request that added it.

The data is in [`data/zta-closure/coverage.yml`](https://github.com/WhalerMike/modernization-workbook/blob/main/data/zta-closure/coverage.yml). Everything below is generated from it by `scripts/zta_coverage.py`; edit the data file and regenerate.
