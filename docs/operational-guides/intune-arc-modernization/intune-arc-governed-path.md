# Intune + Azure Arc — Governed Path

The same modernization end state, bound to organizational intent and continuous evidence.

## Purpose

The governed path reaches the same end state as the manual path — Arc-onboarded servers, Intune-enrolled endpoints, legacy protocols restricted, Conditional Access enforced — but binds every change to organizational intent. The same operational steps run; governance adds a scoped approval, a recorded decision, and a drift-detection loop.

## What governance adds

- Scoped targeting derived from a canonical attribute model
- Approval reference before state-changing operations
- Continuous observation and drift findings
- Evidence of who approved what, and when
- Ability to detect and respond to divergence after the initial change

## Operating model

Changes are proposed, approved, and applied under the control plane. Observation continues after the change so that drift is visible. The technical configuration of Intune and Azure Arc remains the same as the manual path.

## Bottom line

Governance does not change the target state. It changes how decisions are authorized, recorded, and continuously verified.
