# Verification — Learning path: The SD-WAN Governor and Its Evidence

Files: `docs/training/network-sd-wan/index.md` and its modules, `01-the-governor-before-the-traffic.md` and `02-gate-0-the-ed-26-03-and-kev-floor.md` (phase 1); Modules 3 and 4 follow in phase 2.
Example code: `examples/cisco-sdwan`.
Verified: 2026-11-24

Method:
- The path adds no new product, directive or certification facts. Every such fact a module states is carried by link from the Cisco Catalyst SD-WAN implementation guide (`docs/books/guides/cisco-sdwan-implementation.md`, checked against primary sources on October 24, 2026, configuration baseline October 29, 2026, approved November 22, 2026) or Book 09, Chapters 02, 05, 08 and 13, and relies on those pages' verification logs and footnotes (CISA's ED 26-03 and its supplemental guidance, the KEV catalog version 2026.10.23, Cisco's advisories and FedRAMP listing). New writing is limited to the path, the module framing, objectives, unit glue, knowledge-check questions and time estimates.
- No source was read again for the path beyond what the guide's verification log records. The KEV catalog link in Module 2's Lab 2 is the catalog's public page, given so the reader re-reads it.
- Each knowledge-check answer links or names the section that teaches it; the answer was checked against that section's text.
- Every Lab 1 command was run on November 24, 2026 (Windows 11, Python 3.14.3 with pytest 9.0.2, in PowerShell 7.6 and again in Windows PowerShell 5.1), from `examples/cisco-sdwan`, in the order the modules give them, and the output shown is what they printed in PowerShell 7.6. The two editions printed the same rows; `Group-Object` orders groups differently in 5.1, so the labs sort them by name. The test run's time varies and the page says so. Nothing was sent to a fabric: `--replay` reads saved responses and opens no connection, which a unit test asserts.
- Lab 2 runs the kit against a test fabric and wasn't run by the authors, as the pages say. Its config-writing step (Module 1, Lab 2, Step 1) was run in both PowerShell editions with fictional values and a three-row build record, and the kit's own loader accepted the file; with no credentials set, the live run stops with exit code 1 and the message the page describes.
- Training-module exercises aren't captured by `scripts/kit_captures.py` (it reads developer workbook chapters only), so the modules show the output as text; their command lists are generated by `scripts/generate_labs.py`, which registers this path as a kit path (`KIT_PATHS`).
- Time estimates are the program's planning figures *(design guidance)*, not measurements.
- Claim wording: the outputs *support* the controls; the assessor decides them. KSIs are written as indicators for cloud service providers that the agency lines its evidence up with. Control-to-KSI pairs come from Book 13, Appendix A (CM-8 KSI-PIY-GIV, SI-2 KSI-CMT-VTD, RA-5 KSI-SCR-MON, CA-7 KSI-MLA-EVC, AC-6 KSI-IAM-ELP) and, for SC-7, the Azure Security and Global Secure Access guides' tables (KSI-CNA-ULN).
