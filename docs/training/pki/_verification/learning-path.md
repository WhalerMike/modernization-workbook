# Verification — Learning path: PKI and Certificates

Files: `docs/training/pki/index.md` and its modules, `01-what-ad-cs-holds-up.md` and `02-hardening-what-stays.md` (phase 1 of the path).
Example code: `examples/start-kit` (module `FMPADAssessment` 1.6.0, kit 1.5.0).
Verified: 2026-11-24

Method:
- The path adds no new facts about PKI. Every fact a module states is carried by link from Book 07 (`docs/books/b07-pki/`, Chapters 01, 02 and 03 and Appendix B, as on `origin/main` on November 24, 2026) and relies on those chapters' verification logs and footnotes (Microsoft Learn's AD CS, Cloud PKI, Intune certificate and Defender for Identity pages; SpecterOps's 2021 research for the ESC labels). New writing is limited to the path, the module framing, objectives, unit glue, the table of what the Start Kit collects, knowledge-check questions and time estimates.
- No Learn page was read again for the path beyond what Book 07's verification logs record.
- **What the kit collects.** Module 1's Unit 4 table and Module 2's Unit 2 table were checked against the code of `Get-FMPPKIAssessment` and `Get-PKISecurityFindings` in `FMPADAssessment.psm1`: the attributes it reads, the broad principals (`Authenticated Users`, `Domain Users`, `Domain Computers`, `Everyone`), the authentication EKUs, the rights it counts as write, and the absence of an owner check for ESC4.
- **Kit changes for the labs**, each with Pester tests (`tests/powershell/PkiSnapshot.Tests.ps1`): `Get-FMPPKIAssessment -PkiDataPath` reads a snapshot file instead of a directory and a CA; each CA's audit filter (`certutil -getreg CA\AuditFilter`) is recorded in the inventory; `Get-FMPTemplateClassification` copies Appendix B's class and target for the AD CS default templates; `Compare-FMPAssessments` compares `PKISecurityReport.json` by finding and template. Two Windows PowerShell 5.1 fixes came with them: a template's EKU list is written as a JSON array, not a `{value, Count}` wrapper, and a CA certificate read from base64 is passed to the constructor as a byte array. CA certificate dates are now written in UTC. The kit stays read-only: the safety tests pass on every source file.
- **`TemplateMatrix.csv`.** One row per Appendix B row whose template is an AD CS default; the template names (`cn`) are the defaults Microsoft's certificate template reference lists, which Appendix B footnotes. Classes and targets are Appendix B's, shortened; the custom rows (NDES SCEP, PKCS, Windows Hello for Business, the LDAPS row) have no default name and are left to the owner.
- **The fixture.** `tests/fixtures/pki-contoso.json` is fictional: Contoso, `contoso.example`, generated CA certificates under a generated root. The `certutil -getreg` text follows certutil's output format; the EditFlags values are the policy module's default (`0x11014e`) and the default with `EDITF_ATTRIBUTESUBJECTALTNAME2` (`0x15014e`).
- **Lab 1.** Every Lab 1 command was extracted from the two pages and run as printed on November 24, 2026 (Windows 11, Windows PowerShell 5.1), from `examples/start-kit`, Module 1 then Module 2, with `$HOME\fmp-labs\pki` empty first. The output shown is what they printed, with trailing spaces removed. Nothing read a directory or a CA.
- **Tests.** 321 Pester tests pass (with the DNS path's tests from main) in PowerShell 7 and in Windows PowerShell 5.1 (Pester 5.9 loaded by path).
- **Lab 2** runs in a test forest and on a test CA, and wasn't run by the authors, as the pages say. Its CA commands are Book 07 Chapter 03's (`certutil -getreg`, `certutil -setreg CA\AuditFilter 127`, `certutil -setreg policy\EditFlags -EDITF_ATTRIBUTESUBJECTALTNAME2` and its `+` form, `Restart-Service certsvc`, `Backup-CARoleService`). `auditpol /set /subcategory:"Certification Services"` is the local form of the GPO setting the chapter names, for a test CA only; `certutil -view ... csv` is the administrator-run export of the issued-certificate database that the kit's README names for Tier B.
- **Severity.** The kit's `Severity` values for ESC2 and ESC4 differed from Chapter 03's risk-scoring matrix (kit: ESC2 High, ESC4 Critical; book: ESC2 Critical, ESC4 High). The owner decided on November 24, 2026 to change the kit to match the book. `Get-PKISecurityFindings` and the copy of the module in Book 02, Appendix B now rate ESC2 Critical and ESC4 High, a test checks every rating against the matrix, and Module 2 shows the kit's `Severity` column. The Book 07 decks already quoted the book's matrix, so none needs re-recording.
- Training-module exercises aren't captured by `scripts/kit_captures.py` (it reads developer workbook chapters only), so the modules show the output as text; their command lists are generated by `scripts/generate_labs.py`, which now registers this path.
- Time estimates are the program's planning figures *(design guidance)*, not measurements.
- Claim wording: the outputs *support* the controls; the assessor decides them. KSIs are written as indicators for cloud service providers that the agency lines its evidence up with. Only control-to-KSI pairs in Book 13, Appendix A appear; AU-2 and AU-12 have none there, and the module says so.
