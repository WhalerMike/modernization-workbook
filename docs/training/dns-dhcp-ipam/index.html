Learning path: DNS, DHCP and IPAM

Modules on Book 08’s naming plane: read it from the evidence, sort what Active Directory DNS does into where it goes, with a lab on fixtures and a lab in your own test domain

Topic: DNS, DHCP and IPAM (every guide, lab, video and download on it)

Download (Word): this page · Learning path: DNS, DHCP and IPAM (the whole edition)

A learning path for DNS and DDI engineers, Active Directory engineers, network and cloud engineers and ISSO reviewers, built on Book 08, DNS, DHCP & IPAM, and the Start Kit’s DNS and DHCP collectors: read a domain’s zones, locator records, zone health and DHCP scopes as one naming plane, then sort every Active Directory DNS component into Chapter 10’s target, method and risk, with the findings to clear before anything moves. Each module’s Lab 1 runs the Start Kit on a fictional domain’s files with no server; its Lab 2 runs the same commands in your own test domain; each module ends with a knowledge check.

Status — Draft

This page is still being written. Expect gaps and changes; it is not part of the workbook's production guidance.

In most agencies DNS, DHCP and IPAM grew up as a utility on the domain controllers, and nobody owns the whole of it. Book 08 argues that the naming plane is now a control plane: identity, private cloud connectivity and security policy all depend on a name resolving to the right address from every place a client sits. This learning path teaches you to read that plane from evidence rather than from memory, and to plan its move off Active Directory DNS one component at a time. You run the Start Kit’s DNS and DHCP collectors and its readiness checks on your laptop, then in a test domain.

Like a Microsoft Learn learning path, it is a short series of modules, each built on the one before. The modules don’t repeat Book 08. They tell you what to read, in what order, what to run, and what to check you understood.

Who this path is for

Role What you get from the path
DNS or DDI engineer Every zone, forwarder and scope in one inventory, and each one’s target, method and risk on the new platform
Active Directory engineer The locator records, secure dynamic updates and DHCP registration that AD DNS provides, and what must replace each before the last domain controller goes
Network or cloud engineer The DHCP options and forwarders that decide which resolver a client uses, and where cloud private DNS joins the plane
ISSO reviewer The federal requirements each module supports, the KSI it lines up with where the workbook has a verified pairing, and the evidence you keep

Level: intermediate. Products: Windows Server DNS and DHCP with Active Directory Domain Services (Windows Server 2019 or later), the Windows Server DnsServer and DhcpServer PowerShell modules. Scope: a civilian agency at FedRAMP Moderate, in Microsoft 365 GCC with commercial Azure, with an on-premises Active Directory whose domain controllers run DNS, as Book 08 assumes.

Prerequisites

  • Book 08, Chapter 01: fifteen minutes, and every module refers back to it.
  • PowerShell basics: you can run a command, import a module and read the objects it returns.
  • For Lab 1: Windows PowerShell 5.1 or PowerShell 7, and the Start Kit (below). Nothing else.
  • For Lab 2: a test domain you can build and throw away. What you need for the labs says what it holds.

Get the code

Download start-kit.zip to your Downloads folder. It holds the Start Kit, in one folder, start-kit: the DNS and DHCP collectors in FMPADAssessment, the readiness checks in FMPDdiReadiness, their tests, and the fictional domain’s files the labs read, in tests/fixtures/ddi. Unzip it into Downloads\start-kit, the folder Windows’ Extract All suggests, so you work in Downloads\start-kit\start-kit: the zip’s name appears twice. Every lab command runs from there, as it does from examples/start-kit in a clone of the repository. The kit is Windows PowerShell 5.1 or PowerShell 7; it has no Python steps. Get a path’s code says why each step is there.

In PowerShell (Windows PowerShell 5.1 or PowerShell 7):

Expand-Archive -Path $HOME\Downloads\start-kit.zip -DestinationPath $HOME\Downloads\start-kit -Force
Set-Location $HOME\Downloads\start-kit\start-kit
Get-ChildItem $HOME\Downloads\start-kit -Recurse -File | Unblock-File

In Bash on Linux or macOS, or Git Bash on Windows:

unzip -o ~/Downloads/start-kit.zip -d ~/Downloads/start-kit
cd ~/Downloads/start-kit/start-kit

Check it works, in PowerShell, with Module 1, Lab 1, Step 2:

$inv = Get-Content -Raw tests/fixtures/ddi/run-2026-11-20/contoso.example/DNS/DNSInventory.json | ConvertFrom-Json
$inv.DnsServer, $inv.Zones.Count

It prints dc01.contoso.example and 12.

What you’ll be able to do

When you finish the path, you’ll be able to:

  • read a domain’s zones, the DNS servers that hold them, its locator records, its zone health and its DHCP scopes from one assessment run, and say what each tells you;
  • spot what Book 08 says to clear before anything moves: a locator record that doesn’t resolve, a DNS server nobody could read, scavenging off, stale and duplicate records, forwarders nobody has tested;
  • sort every Active Directory DNS component into its target, its Azure-native equivalent, its method and its risk, as Chapter 10 does;
  • explain why the locator records stay with a service domain controllers can register in, and why Azure Private DNS can’t host them;
  • hand the ISSO a dated inventory and a departure register they can trace to the run that produced them.

Modules

Work through them in order.

The modules of the DNS, DHCP and IPAM learning path
# Module Book 08 Labs Time
1 Read the naming plane Chapters 01 to 03, and Chapter 10’s Phase 1 Lab 1, Lab 2 50 min
2 The Active Directory DNS departure Chapter 04, and Chapter 10’s “Where each component goes” Lab 1, Lab 2 55 min

Total time: about 1 hour 45 minutes with each module’s Lab 1. Lab 2, in your own test domain, isn’t counted: building the domain takes most of an hour the first time.

Each module follows the same units: an introduction with the federal requirements it supports, learning objectives, prerequisites, two or three concept units, Lab 1, Lab 2, a knowledge check and a summary.

What you need for the labs

Lab 1: a laptop, no server. Every Lab 1 runs the Start Kit against the files of a fictional domain, contoso.example, in tests/fixtures/ddi/run-2026-11-20: the files Get-FMPDNSAssessment and Get-FMPDHCPInventory write, for three domain controllers and two DHCP servers. The kit’s tests run the real collector under mocks and read its output with the same checks, so the fixture keeps the collectors’ shape. You need the kit and Windows PowerShell 5.1 or PowerShell 7, on Windows, Linux or macOS. Run every command from examples/start-kit (or Downloads\start-kit\start-kit). A lab that writes anything writes an out folder there and deletes it at the end. Nothing in Lab 1 contacts a server. The output shown in each Lab 1 is what the commands printed on November 24, 2026, in PowerShell 7.6 and Windows PowerShell 5.1.

Lab 2: your own test domain. Lab 2 needs one Windows Server 2019 or later virtual machine that you can checkpoint and throw away, promoted to a new forest with fictional names (the labs use lab.contoso.example), with the DNS Server and DHCP Server roles. Module 1’s Lab 2 builds it with Microsoft Learn’s commands. Never run Lab 2 against a production domain: the collectors only read, but the build steps create a forest. The authors didn’t run the Lab 2 steps. Each one ends with a way to back it out, and restoring the checkpoint backs out everything.

How this path fits with the other pieces

Book 08 has no developer workbook: its only code is the Start Kit’s DNS and DHCP collectors and the readiness checks this path added beside them, so the labs run the kit directly, as the Zero Trust Assessment path does with its results kit.

This path teaches Book 08’s platform-neutral design with the workbook’s own code, before and whatever the platform choice (Chapter 12). Take the Infoblox paths once the platform is chosen; they don’t replace these modules, and these modules don’t teach the product.

Title Description
Module 1: Read the naming plane Book 08, Chapters 01 to 03 and Chapter 10’s Phase 1: why DNS, DHCP and IPAM are now a control plane, how split-brain DNS fails without a DNS error, what the federal requirements ask of the name layer, and what an inventory must collect before anything moves. Lab 1 reads a fictional domain’s zones, DNS servers, locator records, zone health and DHCP scopes from the Start Kit’s files; Lab 2 builds a test domain and collects the same files from it. About 50 minutes, with a knowledge check.
Module 2: The Active Directory DNS departure Book 08, Chapter 04 and Chapter 10’s “Where each component goes”: what AD-integrated DNS and Windows DHCP actually do for a domain, why the locator records stay with a service domain controllers can register in, and where every other zone, forwarder and registration goes, how, and at what risk. Lab 1 builds the departure register for a fictional domain with the Start Kit’s Get-FMPDnsDepartureRegister and reads its findings; Lab 2 builds it for your test domain and checks the DHCP registration settings by hand. About 55 minutes, with a knowledge check.
