# Verification — Learning path: Provider Notices

Files: `docs/training/provider-notices/index.md` and its nine modules, `01-why-provider-notices-go-unread.md` to `09-deploying-to-test-and-production.md`.
Example code: `examples/provider-notices` (with `deploy/` for Module 9), and `examples/servicenow-sailpoint` for Module 7's router test.
Verified: 2026-11-09

Method:
- The path adds no new facts. Every fact a module states is carried by link from the provider notices implementation guide (`docs/books/guides/provider-notices-implementation.md`, approved November 9, 2026), the developer workbook *Building Provider Notices* (Chapters 01 to 08) or Book 15, Chapter 14, and relies on those pages' own verification logs and footnotes (Microsoft Learn for Azure and Microsoft 365, Oracle's documentation for OCI, AWS's for AWS Health, Google Cloud's for Personalized Service Health; NIST's OSCAL catalog and fedramp.gov for controls and KSIs). New writing is limited to the path, the module framing, objectives, unit glue, knowledge-check questions and time estimates.
- No provider page was read again for the path: no module states a provider fact the guide, the workbook or Book 15 doesn't already carry with its source.
- Each knowledge-check answer links the section that teaches it; the answer was checked against that section's text.
- Every Lab 1 command in the modules was run on November 9, 2026 (Windows 11, PowerShell 7 with Pester 5), with `scripts/kit_captures.py`'s own PowerShell harness (one session per module, statement by statement, tables at full width), in a scratch copy of `examples/`, in the order the modules give them. The output was compared with the workbook chapters' Lab 1 captures in `data/kit-captures/pn/` and, for the commands no chapter captures, pasted from that run. Nothing was sent to a tenant, account, tenancy or project.
- Training-module exercises aren't captured by `scripts/kit_captures.py` (it reads the workbook chapters only), so the modules have no terminal images; their command lists are generated by `scripts/generate_labs.py`, which now registers this path.
- Lab 2 is a pointer to each chapter's Lab 2 (Module 9: to Chapter 08's stages) and wasn't run, as the pages say.
- Time estimates are the program's planning figures *(design guidance)*, not measurements.
- Claim wording: the records *support* the controls; the assessor decides them. KSIs are written as indicators for cloud service providers that the agency lines its evidence up with. Only the control-to-KSI pairs in the kit's `config/requirements.json` (as the guide and chapters use them) appear.
