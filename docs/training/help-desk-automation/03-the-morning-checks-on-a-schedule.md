# Module 3: The morning checks on a schedule {.unnumbered}

*Part of the [Help Desk Automation learning path](index.md). Book 15, Chapter 12, tasks 6, 7 and 8. Workbook [Chapter 03](../../project-plans/developer-workbooks/help-desk-automation/03-scheduled-checks-sync-roles-and-logs.md). About 50 minutes.*

## Introduction (3 minutes)

Three of the desk's standing chores answer questions a read-only job can answer before anyone arrives: did synchronization run, and did anything break; does every custom role still have exactly its approved permissions; and is every server still sending its event logs somewhere the administrators can't change them. Each job here reads with the help desk audit reader app, writes a dated folder whose manifest hashes every file, and exits 2 when it found something, so the scheduler's history shows it.

**The federal requirement.**

| Requirement | KSI | Evidence |
|---|---|---|
| CA-7; SI-4; AU-6; CP-9: synchronization and service health every morning | KSI-MLA-EVC; KSI-MLA-OSM | `status.json`, `report.md`, `findings.json` |
| AC-2; AC-6; AC-6(7): custom roles against the approved register | KSI-IAM-ELP; KSI-IAM-JIT | `roles.json`, `findings.json` |
| AU-2; AU-6; AU-9; AU-11: event logs forwarded, not written to a share | KSI-MLA-OSM; KSI-MLA-LET; KSI-MLA-RVL | `servers.json`, `findings.json`, the data collection rule |

The outputs support these controls; the assessor decides them. KSIs are FedRAMP 20x indicators for cloud service providers; the mapping is the program's *(design guidance)*.

## Learning objectives (1 minute)

After this module, you'll be able to:

- say when the synchronization check calls a cycle late, and why;
- read the morning report's "changed since the last run";
- name the four role review findings;
- tell a server that isn't associated with the rule from one that has gone silent;
- run a job as the scheduled task would and read its exit code.
