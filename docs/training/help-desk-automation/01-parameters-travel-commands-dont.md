# Module 1: Parameters travel, commands don't {.unnumbered}

*Part of the [Help Desk Automation learning path](index.md). Book 15, Chapter 12, task 5. Workbook [Chapter 01](../../project-plans/developer-workbooks/help-desk-automation/01-the-typed-change.md). About 50 minutes.*

## Introduction (3 minutes)

When a requester writes the command and an operator runs it under administrator rights, the requester is the author and the operator is only the engine. A spoofed mailbox then gets arbitrary execution in the tenant. Book 15's rule is that the request supplies validated inputs to a pre-approved script, and the script is the only thing that runs.

In this module you plan a change to one fictional user, read the plan an approver would approve, watch the kit refuse bad requests, and apply the plan with its hash.

**The federal requirement.** The typed change supports AC-2, AC-6 and CM-3. The output is evidence for these controls; your organization still sets their parameters, and the assessor decides whether each is satisfied. The workbook chapter's [Federal requirements and evidence](../../project-plans/developer-workbooks/help-desk-automation/01-the-typed-change.md#federal-requirements-and-evidence) table has a row for each part of the lab.

| Requirement | KSI | Evidence |
|---|---|---|
| AC-2; CM-3: the request is checked and the change planned | KSI-CMT-LMC | `findings.json`, `plan.json` and `plan.sha256` |
| AC-2; AC-6; CM-3: the change runs only with the approved hash, and is re-read | KSI-CMT-LMC; KSI-IAM-JIT | `evidence.json`, and in Lab 2 the role's activation for the ticket |

KSIs are FedRAMP 20x indicators for cloud service providers. The agency lines this evidence up with what its providers report against them; it doesn't report KSIs itself. Which file supports which indicator is the program's mapping *(design guidance)*.

## Learning objectives (1 minute)

After this module, you'll be able to:

- name the only three things a typed change request may carry;
- read a plan and say what an approver approves;
- name the check that refuses a synchronized user, a disabled user, an unknown change and a value that moved;
- show that a change applies only with its approved hash.
