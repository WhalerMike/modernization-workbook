# Module 4: From catalog item to approval {.unnumbered}

*Part of the [Help Desk Automation learning path](index.md). Book 15, Chapter 12, tasks 1, 2, 4 and 5. Workbook [Chapter 04](../../project-plans/developer-workbooks/help-desk-automation/04-requests-in-servicenow-and-sailpoint.md). About 40 minutes.*

## Introduction (3 minutes)

A request that can say anything has to be read by a person. [WD-182](../../about/decision-register.md#wd-182) makes every request-driven task a ServiceNow catalog item with typed variables, handed through the agency's system access management tool to SailPoint, whose approval scheme for that task decides it. ServiceNow records the request and never approves it ([WD-174](../../about/decision-register.md#wd-174)). The pipeline reads each approval back from SailPoint with one scope, `idn:access-request-status:read`. [WD-184](../../about/decision-register.md#wd-184), a draft amendment to WD-182 awaiting approval, has the test stage prove that the pipeline's API client can make that read. If it can't, the pipeline uses a dedicated identity's personal access token holding only that scope.

In this module you read the kit's templates for both systems and the fixture queue's approvals, so you can say for each task what the requester types, what the agent records and who approves.

**The federal requirement.**

| Requirement | KSI | Evidence |
|---|---|---|
| AC-2; AC-6; CM-3: a request carries only typed variables | KSI-CMT-LMC | The catalog item definitions |
| AC-2; IA-5; IA-12: each task approved in SailPoint by its own scheme | KSI-IAM-JIT | The access profiles |
| IA-5; IA-12: a reset waits for recorded verification | KSI-IAM-JIT; KSI-IAM-SUS | The verification fields and the hand-off |

The configuration supports these controls; the assessor decides them *(design guidance for the KSI mapping)*.

## Learning objectives (1 minute)

After this module, you'll be able to:

- list each catalog item's variables, and say which two need the agent's verification;
- name the field that ties a ServiceNow request to its SailPoint approval, and who writes it;
- read an access profile's approval scheme;
- say why the authenticator reset has two approval steps.

```powershell
# Step 1: Get a SailPoint token
$isc = 'https://<tenant>.api.identitynow.com'
$tok = (Invoke-RestMethod -Method POST -Uri "$isc/oauth/token" -ContentType 'application/x-www-form-urlencoded' -Body @{ grant_type = 'client_credentials'; client_id = '<pat-client-id>'; client_secret = '<pat-client-secret>' }).access_token
$h = @{ Authorization = "Bearer $tok"; Accept = 'application/json' }

# Step 2: Create the four access profiles from your copy, and keep their ids
$made = foreach ($p in (Get-Content '<profiles-file>' -Raw | ConvertFrom-Json).accessProfiles) {
    Invoke-RestMethod -Method POST -Uri "$isc/v3/access-profiles" -Headers $h -ContentType 'application/json' -Body ($p | ConvertTo-Json -Depth 8)
}
$made | Format-Table id, name -AutoSize | Out-String -Width 200

# Step 3: Read them back, and compare each approval scheme with the template
foreach ($m in $made) { $r = Invoke-RestMethod -Uri "$isc/v3/access-profiles/$($m.id)" -Headers $h; '{0}: {1}' -f $r.name, (($r.accessRequestConfig.approvalSchemes | ForEach-Object approverType) -join ' then ') }

# Step 4: Check the developer instance's catalog items and their variables against the template
$sn = 'https://<instance>.service-now.com/api/now/table'
$cred = [pscredential]::new('<admin-user>', (ConvertTo-SecureString '<admin-password>' -AsPlainText -Force))
$names = (Get-HtConfig request-items).items.Keys -join ','
(Invoke-RestMethod -Uri "$sn/item_option_new?sysparm_query=cat_item.nameIN$names&sysparm_fields=name,cat_item.name" -Credential $cred -Authentication Basic -Headers @{ Accept = 'application/json' }).result | Sort-Object 'cat_item.name', name | Format-Table 'cat_item.name', name -AutoSize | Out-String -Width 200

# Step 5: Back out
foreach ($m in $made) { Invoke-RestMethod -Method DELETE -Uri "$isc/v3/access-profiles/$($m.id)" -Headers $h | Out-Null; "deleted $($m.name)" }
foreach ($m in $made) { try { Invoke-RestMethod -Uri "$isc/v3/access-profiles/$($m.id)" -Headers $h | Out-Null; "$($m.name) still exists" } catch { "$($m.name): $($_.Exception.Response.StatusCode)" } }
Remove-Variable tok, h, cred
```
:::
