## Introduction (3 minutes)

A rebuilt screen is an alteration under the Revised 508 Standards, so a modernized front end must conform to WCAG 2.0 Level A and AA. In this module you run an automated rule check on every screen state in the pipeline, see it catch a broken control, and learn what it leaves to a trained tester.

**The federal requirement.** The output of this module's lab is evidence for these controls; your organization still sets their parameters, policy and procedures, and the assessor decides whether each is satisfied. The workbook chapter's [Federal requirements and evidence](../../project-plans/developer-workbooks/application-modernization/05-the-front-end-its-accessibility-check-and-the-containers.md#federal-requirements-and-evidence) table has a row for each lab step, and the kit's `config/requirements.json` holds the mapping.

| Requirement | KSI | Evidence |
|---|---|---|
| CM-3(2), Testing, Validation, and Documentation of Changes | KSI-CMT-VTD | The test results and `a11y-report.json` |
| Section 508; the Revised 508 Standards; OMB M-24-08 | — | The automated report beside the tester's manual record |

KSIs are FedRAMP 20x indicators for cloud service providers. The agency lines this evidence up with what its providers report against them; it doesn't report KSIs itself. Which file supports which indicator is the program's mapping *(design guidance)*.

## Learning objectives (1 minute)

After this module, you'll be able to:

- explain why a rebuilt front end falls under the Revised 508 Standards;
- run the WCAG 2.0 A and AA rules on every screen state, and show the check can fail;
- say what the automated check can't decide, and what a trained tester does instead;
- build the app and know what Lab 2's container run proves for the first time.

1. **Install the exact packages the lock file names:**

    ```powershell
    Set-Location web
    npm ci --no-audit --no-fund --silent
    ```

    Quiet means done: it prints nothing. The first run downloads about a hundred packages and takes a few minutes.

2. **Run the component tests and the accessibility check:** `A11Y_REPORT_DIR` tells the accessibility check where to write its report: this run's folder.

    ```powershell
    $env:A11Y_REPORT_DIR = $Run
    npx vitest run --reporter=json --outputFile="$Run\vitest.json"
    Remove-Item Env:A11Y_REPORT_DIR
    Import-Module ../powershell/AppModernization/AppModernization.psm1
    Get-AmVitestResult -Path "$Run\vitest.json" | Format-Table
    ```

    Expected output:

    ```text
    JSON report written to C:/FMWLabs/results/application-modernization-05-the-front-end-and-section-508/lab1/<run>/vitest.json

    File          Tests Passed Failed
    ----          ----- ------ ------
    a11y.test.jsx     4      4      0
    App.test.jsx      6      6      0
    ```

    Ten tests in two files, none failed.

3. **Read the accessibility report:**

    ```powershell
    $a = Read-AmJson -Path "$Run\a11y-report.json"
    $a.standard; $a.engine; $a.rulesOff
    $a.states | ForEach-Object { [pscustomobject]@{ State = $_.state; Violations = (@($_.violations) | ForEach-Object { "$($_.rule) ($($_.wcag -join ' '))" }) -join ', ' } } | Format-Table -Wrap
    ```

    Expected output:

    ```text
    WCAG 2.0 Level A and AA (axe-core tags wcag2a, wcag2aa)
    axe-core 4.14.1

    color-contrast
    --------------
    jsdom has no layout or paint; check contrast in a browser


    State                                                        Violations
    -----                                                        ----------
    case list
    case detail, agent result and pending proposal
    case not found
    probe: unnamed button and unlabeled input (expected to fail) button-name (wcag412), label (wcag412)
    ```

    No violations on the three screen states; the probe fails `button-name` and `label`, both WCAG 4.1.2. Contrast is off, with the reason.
