## Introduction (3 minutes)

Fifty applications through the factory should leave fifty packs an assessor can read the same way. In this module you finish the fictional application from Module 6: compare it before and after, read the sign-ins since the change, explain the one new error, seal the pack, and catch an edit made after sealing.

**The federal requirement.** The output of this module's lab is evidence for these controls; your organization still sets their parameters, policy and procedures, and the assessor decides whether each is satisfied. The workbook chapter's [Federal requirements and evidence](../../project-plans/developer-workbooks/application-modernization/07-the-post-change-test-and-the-evidence-pack.md#federal-requirements-and-evidence) table has a row for each lab step, and the kit's `config/requirements.json` holds the mapping.

| Requirement | KSI | Evidence |
|---|---|---|
| CA-7, Continuous Monitoring | KSI-MLA-EVC | The sign-ins after the change and the backout triggers |
| CM-8, System Component Inventory | KSI-PIY-GIV | The after snapshot |
| AU-9, Protection of Audit Information | KSI-MLA-OSM | `SHA256SUMS.txt` and the evidence chain |

KSIs are FedRAMP 20x indicators for cloud service providers. The agency lines this evidence up with what its providers report against them; it doesn't report KSIs itself. Which file supports which indicator is the program's mapping *(design guidance)*.

## Learning objectives (1 minute)

After this module, you'll be able to:

- compare an application's before and after snapshots;
- tell a new sign-in error from an old one, and clear only the ones the change was meant to cause;
- seal a pack, and show a later edit;
- line every kit step's evidence up with its controls and KSIs.

## Knowledge check (5 minutes)

    a. Yes, always
    b. It's flagged as new since the change until it's explained; WP5 was meant to cause it, so it's listed with `-Explained` and in the test record

    d. Only if it happens three times

    a. To count more sign-ins

    a. It proves a file changed after sealing; it doesn't stop anyone writing to it, so the ISSO keeps the pack where only they can write
