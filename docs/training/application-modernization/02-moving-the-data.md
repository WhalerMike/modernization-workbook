## Introduction (3 minutes)

Legacy data breaks careless migrations in the same few places. In this module you load a synthetic Db2-style database with the kit's migration tool and put each legacy value beside the loaded one, so you can name the rule that changed it, and see that the tool guesses nothing.

**The federal requirement.** The output of this module's lab is evidence for these controls; your organization still sets their parameters, policy and procedures, and the assessor decides whether each is satisfied. The workbook chapter's [Federal requirements and evidence](../../project-plans/developer-workbooks/application-modernization/02-moving-the-data-the-transform-and-the-load.md#federal-requirements-and-evidence) table has a row for each lab step, and the kit's `config/requirements.json` holds the mapping.

| Requirement | KSI | Evidence |
|---|---|---|
| CM-3(2), Testing, Validation, and Documentation of Changes | KSI-CMT-VTD | The migration test report; `edge-cases.csv` |
| CM-3, Configuration Change Control | KSI-CMT-LMC | The load's report, kept with the change record |

KSIs are FedRAMP 20x indicators for cloud service providers. The agency lines this evidence up with what its providers report against them; it doesn't report KSIs itself. Which file supports which indicator is the program's mapping *(design guidance)*.

## Learning objectives (1 minute)

After this module, you'll be able to:

- name the transform rules a Db2 or Oracle migration needs, and the one class that holds them;
- explain why an unknown code or an amount needing rounding stops the run;
- read the report's mode, source zone, counts and watermark;
- say what the H2 stand-in can't prove about real Db2 or Oracle.

1. **See the legacy habits in the schema:**

    ```powershell
    Select-String -Path migration/src/main/resources/legacy/db2-schema.sql -Pattern 'CHAR\(|DATE|DECIMAL|TIMESTAMP' | ForEach-Object { $_.Line.Trim() }
    ```

    Fixed-width text, a `NOT NULL` closing date with a default of `0001-01-01`, a decimal amount and a timestamp with no zone.

2. **Run the migration tests and the lab reports:**

    ```powershell
    ./mvnw -q -pl migration test "-Dtest=MigrationTest,LabReportsTest"
    Import-Module ./powershell/AppModernization/AppModernization.psm1
    Get-AmTestResult -Path migration/target/surefire-reports | Format-Table
    ```

    No failures or errors in `MigrationTest` or `LabReportsTest`.

3. **Put each legacy value beside the loaded one:**

    ```powershell
    Import-Csv migration/target/lab/edge-cases.csv | Format-Table
    ```

    Padding gone from keys and names (quoted so you can see it), `C`/`P`/`O` as words, the sentinel as `NULL`, the smallest and largest amounts exact, the timestamp as a UTC instant to the microsecond, and `Peña` and `Zoë` intact.
