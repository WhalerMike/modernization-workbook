## Introduction (3 minutes)

A legacy application isn't rewritten all at once: Book 18 gives each application a disposition, and the ones that are refactored or rebuilt land on one target architecture, API-first, with a service that owns its data. In this module you see the reference implementation's service hold to that: a contract that can't drift from the code without a red build, errors a machine can read, and a schema that exists in exactly one file.

**The federal requirement.** The output of this module's lab is evidence for these controls; your organization still sets their parameters, policy and procedures, and the assessor decides whether each is satisfied. The workbook chapter's [Federal requirements and evidence](../../project-plans/developer-workbooks/application-modernization/01-the-contract-and-the-schema-the-service-owns.md#federal-requirements-and-evidence) table has a row for each lab step, and the kit's `config/requirements.json` holds the mapping.

| Requirement | KSI | Evidence |
|---|---|---|
| CM-3(2), Testing, Validation, and Documentation of Changes | KSI-CMT-VTD | The contract and API test reports; the evidence record |
| CM-2, Baseline Configuration | KSI-SVC-ACM | `openapi.yaml` and `V1__baseline.sql`, hashed in the record |

KSIs are FedRAMP 20x indicators for cloud service providers. The agency lines this evidence up with what its providers report against them; it doesn't report KSIs itself. Which file supports which indicator is the program's mapping *(design guidance)*.

## Learning objectives (1 minute)

After this module, you'll be able to:

- explain why Book 18 modernizes a portfolio one application at a time, and what *API-first* asks of a service;
- show from a test run that the service implements exactly the operations its contract documents;
- read a problem details body and say which code produced it;
- find the one file the schema lives in, and say why the migration tool doesn't keep a copy.

1. **List what the contract documents:**

    ```powershell
    Import-Module ./powershell/AppModernization/AppModernization.psm1
    Get-AmContractOperation -Path service/src/main/resources/static/openapi.yaml | Format-Table
    ```

    Expected output:

    ```text
    Method Path                           OperationId
    ------ ----                           -----------
    GET    /api/cases                     listCases
    GET    /api/cases/{caseNumber}        getCase
    POST   /api/cases/{caseNumber}/triage triageCase
    GET    /api/proposals                 listProposals
    POST   /api/proposals/{id}/decision   decideProposal
    ```

    Five operations, each with an `operationId`.

2. **Run the contract and API tests, and the lab records:** `clean` empties `service/target` first, so the results show only this run's tests, and `-Dlab.dir` tells the lab records where to write the API's answers: this run's folder.

    ```powershell
    ./mvnw -q -pl service clean test "-Dtest=OpenApiContractTest,CaseApiTest,LabRecordsTest" "-Dlab.dir=$Run\lab"
    ```

    Expected output, once Maven has its dependencies (the first run also downloads Maven, the PostgreSQL binaries and the test libraries, and prints their progress):

    ```text
    OpenJDK 64-Bit Server VM warning: Sharing is only supported for boot loader classes because bootstrap classpath has been appended
    ```

    Quiet means passed: Maven prints nothing unless a test fails. The one line the JVM prints, a warning that class sharing is limited because the test agent extends the class path, is harmless. The run takes a few minutes: the tests start a real PostgreSQL 18 server. The tests' own log is in `service/target/surefire-reports`.

3. **Read the results:**

    ```powershell
    Get-AmTestResult -Path service/target/surefire-reports | Format-Table
    ```

    Expected output:

    ```text
    Class               Tests Failures Errors Skipped
    -----               ----- -------- ------ -------
    LabRecordsTest          3        0      0       0
    CaseApiTest             8        0      0       0
    OpenApiContractTest     2        0      0       0
    ```

    No failures or errors in `OpenApiContractTest`, `CaseApiTest` or `LabRecordsTest`.

4. **See the problem details the service returned:**

    ```powershell
    foreach ($f in 'api-not-found', 'api-bad-number', 'api-bad-status') { $r = Read-AmJson -Path "$Run\lab\$f.json"; [pscustomobject]@{ File = $f; Status = $r.httpStatus; ContentType = $r.contentType; Title = $r.body.title; Detail = $r.body.detail } }
    ```

    Expected output:

    ```text
    File        : api-not-found
    Status      : 404
    ContentType : application/problem+json
    Title       : Not found
    Detail      : Case C-999999 not found

    File        : api-bad-number
    Status      : 400
    ContentType : application/problem+json
    Title       : Invalid request
    Detail      : Case number must match ^C-[0-9]{6}$

    File        : api-bad-status
    Status      : 400
    ContentType : application/problem+json
    Title       : Bad Request
    Detail      : Failed to convert 'status' with value: 'LOST'
    ```

    Every one is `application/problem+json`. The first two come from the kit's handler; the third, a value Spring can't convert to the `status` enumeration, from Spring's own.

5. **Find the schema's single source:**

    ```powershell
    Get-ChildItem -Recurse -Filter 'V*__*.sql' -Path service/src, migration/src | ForEach-Object { $_.FullName.Substring($PWD.Path.Length + 1) -replace '\\', '/' }
    ```

    Expected output:

    ```text
    service/src/main/resources/db/migration/V1__baseline.sql
    service/src/main/resources/db/sample/V100__sample_data.sql
    ```

    Two files: the baseline, and the demo data the `demo` profile adds. The migration tool has no copy.

6. **Write the step's evidence record:**

```powershell
# Step 1: Point the service at the test database
$env:DB_URL = 'jdbc:postgresql://<pg-host>:5432/<database>'

# Step 3: Call it as the contract says
Invoke-RestMethod 'http://localhost:8080/api/cases?status=OPEN' | Format-Table caseNumber, status, openedOn, amountClaimed
Invoke-WebRequest http://localhost:8080/api/cases/C-999999 -SkipHttpErrorCheck | Select-Object StatusCode, @{ n = 'ContentType'; e = { $_.Headers['Content-Type'] } }, Content
(Invoke-WebRequest http://localhost:8080/openapi.yaml).Content.Split("`n")[0..3]

# Step 4: Check Flyway applied one migration, and the demo data
psql -h <pg-host> -U <db-user> -d <database> -c 'select version, description, success from flyway_schema_history order by installed_rank'

# Step 5: Back it out
Stop-Process -Id $svc.Id
psql -h <pg-host> -U <db-user> -d postgres -c 'DROP DATABASE <database>'
Remove-Item service-test.log; Remove-Item Env:DB_URL, Env:DB_USER, Env:DB_PASSWORD
```

- **You need:** a PostgreSQL 16 or later test server with an empty database you may drop, `psql`, and Java 21; never production.
- **What you do:** point the service at the database, start it with the demo data, call each operation as the contract says, and read Flyway's history table.
- **Back-out:** stop the service, drop the test database and clear the session's environment variables.
