# Module 8: Shutting down a retired application {.unnumbered}

*Part of the [Application Modernization learning path](index.md). Book 18, [Appendix B](../../books/b18-application-modernization/appendix-b-shutting-down-a-retired-application.md). Workbook [Chapter 08](../../project-plans/developer-workbooks/application-modernization/08-shutting-down-a-retired-application.md). About 45 minutes.*

## Introduction (3 minutes)

An application switched off in one change still has DNS records, certificates, accounts, firewall rules, monitoring sources and licenses in systems it doesn't own. In this module you write the decommission plan for a fictional application at two points in its retirement, read which gate it's blocked at, catch a switch-off that didn't happen, and show that an edited plan no longer matches its manifest.

**The federal requirement.** The output of this module's lab is evidence for these controls; your organization still sets their parameters, policy and procedures, and the assessor decides whether each is satisfied. The workbook chapter's [Federal requirements and evidence](../../project-plans/developer-workbooks/application-modernization/08-shutting-down-a-retired-application.md#federal-requirements-and-evidence) table has a row for each, and the kit's `config/requirements.json` holds the mapping.

| Requirement | KSI | Evidence |
|---|---|---|
| CM-8, System Component Inventory | KSI-PIY-GIV | The footprint's items, each flagged until removed |
| AC-2, Account Management | — | The accounts and registration on the removal list |
| AC-2(3), Disable Accounts | KSI-IAM-AAM | The switch-off: sign-in and the service accounts disabled when no longer needed |
| CA-3, Information Exchange | — | The dependents checked against the quiet date |
| SR-12, Component Disposal | — | The removal commands and each team's record |
| SI-12, Information Management and Retention | — | The records officer's confirmation at R3 |
| CM-3, Configuration Change Control | KSI-CMT-LMC | Each removal command, run in its own change at its gate |

KSIs are FedRAMP 20x indicators for cloud service providers. The agency lines this evidence up with what its providers report against them; it doesn't report KSIs itself. Which file supports which indicator is the program's mapping *(design guidance)*.

## Learning objectives (1 minute)

After this module, you'll be able to:

- write an application's decommission plan at any of its gates, and say which gate blocks it and why;
- hand each owning team its removal commands, and keep every removal in its own change;
- tell a switch-off that happened from one that didn't, from the plan;
- show that the plan you file with the authorization closure is the plan the kit wrote.

```powershell
# Step 1: Sign in, and create the application to retire
Connect-MgGraph -TenantId <test-tenant-id> -Scopes 'Application.ReadWrite.All','AuditLog.Read.All' -NoWelcome
$app = New-MgApplication -DisplayName 'Retirement lab (test)'

# Step 2: Write its footprint
New-Item -ItemType Directory -Force out/lab | Out-Null
$fp = Get-Content tests/fixtures/footprint.json -Raw | ConvertFrom-Json -AsHashtable

$fp.entraApps = @(@{ appId = $app.AppId; displayName = 'Retirement lab (test)'; accountEnabled = $true; lastSignIn = $null })
foreach ($k in 'dns', 'certificates', 'accounts', 'firewallRules', 'monitoring', 'licenses', 'dependents') { $fp[$k] = @() }
$today = (Get-Date).ToUniversalTime().Date
$fp.schedule = @{ quietFrom = $today.AddDays(-14).ToString('yyyy-MM-dd'); switchOff = $today.AddDays(-1).ToString('yyyy-MM-dd'); removeAfterDays = 30 }
$fp | ConvertTo-Json -Depth 5 | Set-Content out/lab/footprint.json

# Step 3: Write the plan from the live sign-in state
./Invoke-ArtPlan.ps1 -FootprintPath out/lab/footprint.json -OutputPath out/lab/plan-1 -ReadEntra
Get-Content out/lab/plan-1/findings.json | ConvertFrom-Json | Format-Table Rule, Gate, Object, Issue

# Step 4: Switch it off with the plan's R4 command, and write the plan again
Update-MgServicePrincipal -ServicePrincipalId $sp.Id -AccountEnabled:$false
./Invoke-ArtPlan.ps1 -FootprintPath out/lab/footprint.json -OutputPath out/lab/plan-2 -ReadEntra
Get-Content out/lab/plan-2/plan.json

# Step 5: Back it out
Update-MgServicePrincipal -ServicePrincipalId $sp.Id -AccountEnabled:$true
(Get-MgServicePrincipal -ServicePrincipalId $sp.Id -Property accountEnabled).AccountEnabled
Remove-MgServicePrincipal -ServicePrincipalId $sp.Id
Remove-MgApplication -ApplicationId $app.Id
Remove-Item -Recurse -Force out/lab
Disconnect-MgGraph
```
